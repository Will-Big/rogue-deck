# 문서 수명주기와 색인

**언제 읽나:** 스펙·계획을 추가·완료·대체할 때. AGENTS.md 규칙 20이 이 문서를 가리킨다.
문서 자체의 골격은 [`design-doc-format.md`](design-doc-format.md)에 있다(규칙 28·29).

## 규칙 20 — 문서 색인을 같은 커밋에서 갱신한다

중앙 색인은 [`docs/superpowers/README.md`](../superpowers/README.md) 하나다. 새 스펙·계획을
추가하거나 완료·대체할 때 **같은 커밋에서** 그것을 함께 고친다. 커밋이 갈리면 색인은 반드시
낡는다 — 다음 커밋에서 고치겠다는 의도는 지켜진 적이 없다.

완료된 계획·구현 기록은 `docs/superpowers/.archive/`로 옮기고 **색인에서 그 행을 지운다.**
옮기기만 하고 링크를 남기면 아카이브가 자랄 때 색인도 같이 자라고, 새 세션이 폐기된 문서를
현행으로 착각한다. 2026-08-28에 실제로 그렇게 됐다 — 형제 계획이 아카이브로 옮겨졌는데 백로그의
링크가 남아 깨진 채 방치됐다.

현행 `specs/`와 `plans/`에는 `current` 또는 `active` 문서만 둔다.

**`.archive/`는 읽지 않는다.** 폐기된 이력이며 현재 규칙의 권위가 아니다. 점 디렉터리라 검색
도구가 기본으로 건너뛰므로 별도 조치가 필요 없다(`rg --hidden`으로만 보인다). 그 안의 `규칙 N`
인용은 **작성 당시 기준**이라 지금과 뜻이 다를 수 있다 — 규칙 5는 "ScriptableObject로 저작한다"에서
"JSON으로 저작한다"로, 규칙 17은 "GUI 에디터를 열지 않는다"에서 "직접 저작한다"로 뒤집혔다.

## 상태 어휘

| 상태 | 의미 |
|---|---|
| `current` | 현재 규칙 또는 구현 구조를 설명하는 권위 문서 |
| `active` | 아직 끝나지 않았고 현재 기준으로 실행 가능한 계획 |
| `needs-redesign` | 필요한 영역이지만 기존 문서를 그대로 실행할 수 없음 |
| `archived` | 완료·대체되어 `.archive/`로 옮긴 것. 색인에 남기지 않는다 |

현행 문서끼리 충돌하면 날짜가 아니라 색인의 `권위 범위`와 문서가 명시한 대체 관계를 따른다.

## 옮길 때의 순서

1. 문서를 `docs/superpowers/.archive/{specs,plans}/`로 옮긴다
2. `docs/superpowers/README.md`에서 그 행을 **지운다** (상태만 바꾸지 않는다)
3. `.archive/README.md`의 보관 색인에 행을 더한다
4. 그 문서를 가리키던 현행 문서의 링크를 확인한다 — 본문의 "구현 기록: …" 같은 언급은 완료
   표시이므로 링크를 빼고 문장만 남긴다
5. 셋을 **한 커밋**에 담는다

`pre-commit`이 2번을 검사한다. `specs/`·`plans/`가 추가·삭제·이동됐는데 `README.md`가 스테이지에
없으면 커밋이 막힌다.
