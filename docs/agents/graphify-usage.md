# graphify 지식 그래프 사용

**언제 읽나:** 카드·상태의 관계 질문(어느 카드가 X를 쌓나, 이 핸들러를 고치면 어느 카드가
영향받나), 심볼의 호출자·상속·참조 추적, 그래프 재생성, `cache/semantic` 취급, 유료 `--update`
판단이 필요할 때.

AGENTS.md 규칙 21~24가 이 문서를 가리킨다. 규칙 본문은 판단 기준만 남기고, 근거와 절차는 여기
있다. 도구에 매이지 않는 저장소 문서이며, Claude Code에서는 `.claude/skills/graphify-usage/`가
이 파일을 자동으로 물어 온다.

## 1. 그래프는 커밋되지 않는 로컬 산출물이다. 쓰기 전에 새로 만든다

`graph.json`·`manifest.json`·`GRAPH_REPORT.md`는 `.gitignore`에 있다. 커밋해 두면 조용히 썩기
때문이다 — 2026-08-05 실측으로, 07-31에 커밋된 그래프는 155커밋 만에 4,112노드 중
**697개(17%)가 삭제된 79개 파일을 가리켰다.** `graphify explain "CardAsset"`은 계획 3b가 지운
클래스를 `Assets/Unity/CardAsset.cs L12`와 이웃 23개까지 붙여 **아무 경고 없이** 돌려줬다. 낡은
그래프는 침묵하지 않고 틀린 file:line을 확신 있게 말한다.

조회하기로 했다면 그 전에 한 번, **약 11초·LLM 0토큰**으로 재생성한다:

```bash
Tools/graph/rebuild-graph.sh
```

실측 결과(2026-08-28) 재생성은 AST에 더해 잡음 프루닝(참조 스텁·테스트·외부 패키지·도구, 총
~2,500노드)과 카드·상태·풀·덱 JSON의 서브그래프 병합, 사람용 시각화 2장
(`graphify-out/card-graph.html` 카드 관계망, `graphify-out/architecture.html` 커뮤니티 단위
아키텍처)까지 만든다. 최종 그래프는 게임 로직 코드 + 문서 + 카드 서브그래프 ~3,000노드에 죽은
노드 0%다. 문서 노드가 무료로 살아나는 건 `cache/semantic/`이 커밋되어 있기 때문이다(아래 4절).
증분 갱신은 union 병합이라 유령이 쌓이므로 삭제 후 재생성이 증분보다 싸고 깨끗하다. 갱신을
대신해 주는 훅은 없다 — 그래프 최신성은 오직 위 스크립트로 보장한다.

## 2. 조회는 노드 이름을 알 때만 이득이다. 기본값은 Read·grep이다

규칙 21이 "explain부터"였던 2026-08-01 이후 11세션 5,110메시지에서 자발적 조회는 **1회**였고
Read는 186회였다. 세션들이 규칙을 어긴 게 아니라, 재생성 없이는 답이 틀릴 수 있다는 계산이
맞았다. 그래프를 켤지는 질문의 모양으로 판단한다:

- **카드·상태의 관계 질문이면**(어느 카드가 X를 쌓나/소모하나, 이 핸들러·행동을 고치면 어느
  카드가 영향받나, 시너지 경로) → 그래프가 1순위다. 엣지가 엔진이 실행하는 JSON과
  레지스트리에서만 나오므로(태그 불포함) 답이 정확하고, 같은 답을 Read로 얻으려면 콘텐츠 JSON
  수십 개를 통독해야 한다. `graphify explain "<카드 한글명>"` 또는
  `graphify path "<행동 클래스>" "<카드 한글명>"`. 카드 서브그래프는 전용 엣지를 사용하므로
  아래의 '코드↔코드 path는 허브 경유로 무의미하다'는 경고와 충돌하지 않는다.
- **심볼 이름을 알고 관계(호출자·상속·참조)를 캐야 하면** → `graphify explain "<이름>"`이 이긴다.
  실측: 출력 ~700토큰 vs 원본 파일 통독 ~3,600토큰, 히트당 약 2,900토큰 절약.
- **파일 위치나 문자열을 찾으면** grep이 더 싸다. **파일 하나를 이해해야 하면** Read가 더 정확하다.
- **개념만 알면** `graphify query "<질문>"`으로 **진입점 이름만** 얻고 즉시 `explain`으로 들어간다.
  query 결과를 코드 질문의 답으로 삼지 않는다 — 코드↔문서 엣지가 1.4%뿐이라 자연어 질의는 문서
  노드에 착지한 뒤 코드로 못 건너가고 ~2000토큰 예산에서 잘린다.
- `graphify path "<A>" "<B>"`는 문서↔문서(cites/implements)에서만 믿는다. 코드↔코드는 허브
  노드(`CombatState` 등)를 경유한 무의미한 경로가 나온다.

한 세션에서 관계 질의를 한두 번 할 뿐이라면 재생성 약 11초를 들일 이유가 없다. **그냥 읽어라.**

## 3. `/graphify --update`(문서·이미지 시맨틱 재추출)는 돌리지 않는다

서브에이전트를 쓰는 **유료** 작업이고 회당 25만~40만 토큰이다(2026-08-05 실측: 07-31 이후 변경된
md 34개 = 원문 약 16만 토큰 + 청킹·프롬프트 오버헤드). 회수액은 2절의 히트당 ~2,900토큰이고
실사용 빈도는 5,110메시지당 1회다 — **100배 적자다.** 사용자가 명시적으로 요청할 때만 돌리고,
먼저 이 비용을 알린다. 스스로 제안하지 않는다. (돌리게 되면 `.superpowers/`·
`graphify-out/memory/` 같은 스크래치 산출물은 대상에서 뺀다.)

## 4. `graphify-out/cache/semantic/`은 커밋 대상이다

이 저장소에서 유일하게 값이 나간 산출물이고(문서·이미지 추출 2.28M 토큰, `cost.json` 기록),
저장소 상대 경로만 담고 있어 이식 가능하다. 이게 있어야 1절의 재생성이 문서 노드까지 무료로
복원한다 — **지우면 2.28M 토큰을 다시 태워야 한다.**

반대로 `graph.json`·`manifest.json`·`GRAPH_REPORT.md`·`cache/ast/`·`graph.html`·`cost.json`과
신버전 graphify가 만드는 `.vocab.txt`·`memory/`·`reflections/`는 무료로 재생성되거나 머신 로컬
스크래치라 `.gitignore`에 있다. 캐시 키에 graphify의 추출 프롬프트 해시가
들어가므로(`cache/semantic/p<해시>/`), graphify를 올려 프롬프트가 바뀌면 캐시가 무효화되고
재추출은 유료다.
