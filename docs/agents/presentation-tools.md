# 표현 레이어의 도구 선택

**언제 읽나:** 연출·렌더링·트랜지션·입력 피드백을 만들기 전. AGENTS.md 규칙 32가 이 문서를
가리킨다.

## 판별 기준은 "헤드리스로 검증하는가"

`dotnet test`로 단언할 로직이면 규칙 6·7·12를 따라 직접 구현한다. **눈으로만 확인되는 것이면**
기존 도구를 먼저 쓴다.

경계에 걸치면 **쪼갠다** — 순수 계산은 테스트되는 클래스로, 그것을 화면에 먹이는 부분은 도구로.
`PlacementFlightPath`가 그 예다: 베지에 수학은 `PlacementFlightPathTests`가 덮고, 그 위를 나는
일은 DOTween이 한다.

## 직접 만들어도 되는 때

쓸 도구가 없거나 도구가 요구를 못 맞출 때다. 그때는 **왜 안 썼는지를 설계 문서에 남긴다** —
남기지 않으면 다음 세션이 같은 판단을 처음부터 다시 하고, 대개 반대로 결론 낸다.

## 두 가지 경계

**새 의존성 도입은 여전히 사전 승인이다(규칙 14).** 바뀌는 것은 기본값이다 — 연출 영역에서는
"직접 만들까요"가 아니라 "이 도구를 쓸까요"로 제안한다.

**도구가 코어로 새지 않게 한다.** `FateWeaver.Core`는 어떤 경우에도 이것들을 참조하지 않는다
(규칙 6). 결정론(규칙 7)은 규칙 로직의 것이며, **연출의 난수·시간·프레임률은 해당하지 않는다** —
연출에서 `Time.deltaTime`이나 `Random.value`를 쓰는 것은 위반이 아니다.
