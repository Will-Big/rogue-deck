# 실행 카드 무대상 배치 흐름 설계

> **보관 문서:** 완료되었거나 현재 기준에서 대체된 역사 기록입니다. 현행 규칙의 권위 문서가 아니며, 현재 문서는 [`docs/superpowers/README.md`](../../README.md)에서 확인합니다.

## 1. 목적

실행 카드의 규칙과 입력 흐름을 다음 불변식으로 고정한다.

- 실행 카드는 플레이어가 직접 대상을 선택하지 않는다.
- 실행 카드는 실행 순서를 가진다.
- 실행 카드는 실행 영역에 실행 순서 오름차순으로 배치된다.
- 실행 카드는 턴 종료 시 자동 실행된다.
- 직접 대상 선택은 조작 카드(`Intervention`)만 사용한다.

손패 실행 카드를 호버하면 자동 배치 위치를 정적인 레일 실루엣으로 보여준다. 손패 카드를 클릭하면
실루엣을 배치 버튼으로 고정하고 DOTween 펄스로 두 번째 클릭을 유도한다. 실루엣 클릭이 실제 배치를
확정한다.

이 설계는 `2026-07-17-execution-placement-preview-design.md`의 마우스 추적 카드와 레일 진입 기반
프리뷰 규칙을 대체한다.

## 2. 범위

### 포함

- 모든 플레이어 실행 카드의 무대상 배치 규칙
- 손패 실행 카드 호버 시 정적 레일 실루엣
- 손패 실행 카드 클릭 후 실루엣 DOTween 펄스 및 클릭 배치
- 마우스를 따라다니는 전체 카드 제거
- 실행 카드의 아군·적 직접 선택 UI와 코어 배치 인자 제거
- 레일 실루엣이 있는 동안 기존 레일 카드 상세 호버 허용
- 직접 선택 대상 실행 카드 저작 검증
- 레거시 검증 카드의 자동 대상 마이그레이션
- DOTween 무료판 의존성 추가와 asmdef 연결
- 코어 헤드리스 테스트, Unity EditMode 테스트, 수동 플레이 체크리스트

### 제외

- 조작 카드의 현재 대상 선택·확인 흐름 변경
- 실행 카드 문장 조각 또는 효과를 실제로 바꾸는 조작 시스템 구현
- 조작 카드가 사용할 문장 슬롯, 대상 슬롯, 추가 효과 데이터 모델 설계
- 실행 순서, 상태 효과, 동률 정렬 규칙 변경
- 적 실행 카드의 자동 대상 규칙 변경

## 3. 사용자 상호작용

### 3.1 손패 호버

1. 손패의 실행 카드에 포인터가 들어오면 기존 손패 확대를 적용한다.
2. 상태 효과가 반영된 최종 실행 순서와 자동 삽입 인덱스를 읽기 전용으로 계산한다.
3. 해당 위치에 레일 크기의 반투명·푸른색 실루엣을 즉시 표시한다.
4. 실루엣은 레일 레이아웃에 참여해 뒤쪽 실제 카드들을 한 칸 민다.
5. 호버 단계의 실루엣은 정적이며 확대·축소하지 않고 입력도 받지 않는다.
6. 손패 카드를 클릭하지 않은 채 포인터가 나가면 실루엣을 숨기고 레이아웃을 복구한다.
7. 다른 실행 카드로 호버가 이동하면 같은 실루엣 인스턴스를 새 카드와 새 위치로 갱신한다.
8. 조작 카드 호버는 실행 카드 실루엣을 표시하지 않는다.

### 3.2 손패 실행 카드 클릭

1. 현재 턴, 손패 인덱스, 카드 분류와 운명력을 검증한다.
2. 유효하면 `CardSelectionMachine`을 기존 `ConfirmPlacement` 상태로 전환한다.
3. 실행 카드는 손패에 남고 운명력도 아직 소비하지 않는다.
4. 손패 원본에는 선택 테두리만 표시한다. 반투명 손패 고스트와 마우스 추적 전체 카드는 만들지 않는다.
5. 레일 실루엣은 손패 호버가 끝나도 같은 자동 위치에 고정한다.
6. 실루엣 버튼을 활성화하고 DOTween으로 작은 확대·축소를 무한 반복한다.
7. 기존의 은은한 실행 영역 드롭 힌트도 배치 대기 동안 유지한다.
8. 선택된 실행 카드가 있는 동안 다른 손패 호버는 실루엣을 교체하지 않는다.
9. 기존 레일 카드에 호버하면 실루엣과 별개로 전체 카드 상세보기를 표시한다.
10. 빈 영역 또는 딤 영역을 클릭하면 비용 없이 배치 선택과 실루엣을 정리한다.

### 3.3 실루엣 클릭과 실제 배치

1. 펄스 중인 실루엣을 클릭하면 `ClickApplyArea()`로 배치 완료 결과를 만든다.
2. 세션은 턴 상태, 손패 카드, 운명력과 실행 카드 분류를 다시 검증한다.
3. 최종 실행 순서와 삽입 위치를 실제 배치 경로에서 다시 계산한다.
4. 성공 시 운명력을 차감하고 실행 카드 인스턴스를 미래 영역에 추가한다.
5. 손패 카드를 버린 카드 더미로 옮긴다.
6. 실루엣과 DOTween을 정리하고 실제 레일을 다시 렌더링한다.
7. 실제 카드는 프리뷰와 동일한 정렬 규칙의 위치에 나타난다.
8. 검증 실패 시 카드·운명력·미래 영역을 변경하지 않고 배치 선택을 종료한 뒤 안내한다.

### 3.4 턴 실행

- 미래 영역의 카드는 실행 순서 오름차순으로 자동 실행한다.
- 실행 순서 동률에서는 기존 플레이어 우선 및 안정 정렬을 유지한다.
- 실행 중 플레이어에게 아군·적 대상을 클릭하라는 선택 단계를 열지 않는다.
- 대상은 실행 카드가 가진 자동 대상 규칙 또는 향후 조작 카드로 변경된 실행 인스턴스 규칙이 결정한다.

### 3.5 운명력 부족

- 운명력이 부족해도 실행 카드 호버 실루엣과 예상 위치는 표시한다.
- 손패 클릭 시 배치 대기 상태로 전환하지 않고 기존 부족 안내를 표시한다.
- 정적 실루엣은 손패 호버가 끝날 때 사라진다.

## 4. 코어 규칙

### 4.1 배치 API

`DeckCombatSession.PlayExecutionCard`는 `handIndex`만 받는다. 플레이어가 선택한 `targetId`를 배치
API로 전달하는 경로를 제거한다. `ExecutionCardInstance`의 내부 대상 정보는 적 자동 타게팅과 향후 조작
결과를 표현할 수 있도록 별도 개념으로 유지한다.

실제 배치는 기존 `EffectiveExecutionOrderFor`와 `FutureZone` 정렬 헬퍼를 사용한다. 같은 상태에서
프리뷰와 실제 배치가 다른 순서를 계산하는 중복 로직을 만들지 않는다.

### 4.2 호버 프리뷰

호버 프리뷰는 실행 카드 여부와 턴·손패 유효성을 검사하지만 운명력 부족만으로 거부하지 않는다.
위치 계산은 에너지, 손패, 버림패, 미래 영역, 인스턴스 ID와 RNG를 변경하지 않는다.

실제 배치 가능성 검증과 예상 위치 계산을 분리해, 낼 수 없는 카드도 위치는 학습할 수 있게 한다.

### 4.3 직접 대상 실행 카드 검증

플레이어 기본 실행 카드가 `PartyTargetRules.RequiresExplicitAllyTarget`을 만족하면 세션 부팅 또는 콘텐츠
검증에서 명확한 예외를 발생시킨다. UI에서만 선택을 제거해 영원히 낼 수 없는 카드를 만드는 상태를
허용하지 않는다.

레거시 `fixture_selected_block`과 대응 저작 스펙은 `StatusApplyTarget.Self`로 마이그레이션한다.
`StatusApplyTarget.PartyMember` 같은 내부 표현 자체는 향후 조작된 실행 인스턴스를 표현할 가능성을 위해
삭제하지 않는다.

## 5. Unity 구성 요소

### 5.1 `HandFanView`와 `HandCardHoverEffect`

- `SetCards`가 클릭 콜백과 함께 카드별 호버 시작·종료 콜백을 받는다.
- `HandCardHoverEffect`는 기존 확대/복원을 유지하면서 호버 상태를 상위 뷰로 전달한다.
- 억제 상태에서는 잘못된 종료 콜백으로 선택된 실루엣을 지우지 않는다.

### 5.2 `BattleScreenController`

- 손패 호버 카드가 `Execution`이면 코어 프리뷰를 호출하고 보정된 `CardPresentation`과 삽입 인덱스를
  `CardSelectionController`에 전달한다.
- 실행 카드 클릭은 직접 대상 규칙을 검사하지 않고 모두 `BeginPlacement`로 들어간다.
- 조작 카드만 기존 `CardTargetRules.RequiredRailTargets`와 대상 선택 경로를 사용한다.
- 실제 배치는 선택 컨트롤러가 반환한 무대상 `SelectionResult`로 `PlayExecutionCard(handIndex)`를 호출한다.

### 5.3 `CardSelectionController`

- 선택 머신을 변경하지 않고 `ConfirmPlacement`를 실행 카드의 유일한 선택 상태로 사용한다.
- 선택 전 호버 프리뷰와 선택 후 고정 프리뷰의 소유권을 구분한다.
- `BeginPlacement`는 마우스 추적 카드와 손패 고스트를 만들지 않는다.
- 선택 후 레일 프리뷰를 펄스·클릭 가능 상태로 바꾼다.
- 성공, 실패, 취소와 화면 초기화가 같은 정리 경로에서 실루엣과 tween을 종료한다.

### 5.4 `ExecutionRailView`

레일 프리뷰는 다음 세 표현 상태를 가진다.

- `Hidden`: 비활성, 스케일 1, 입력 없음
- `HoverStatic`: 활성, 알파 0.5, 푸른 테두리, 스케일 1, 입력 없음
- `SelectedPulse`: 활성, 같은 위치와 스타일, 버튼 활성, DOTween 펄스 반복

기존 `RailCardView` 프리팹을 런타임에 하나만 생성해 재사용한다. 새 프리팹이나 새 직렬화 필드는 만들지
않는다. 기존 레일 카드의 전체보기 호버는 프리뷰 상태와 동시에 동작하도록 기존 억제 조건을 제거한다.

실루엣 버튼이 활성화된 동안 실루엣 클릭만 배치를 확정한다. 레일 배경이나 기존 레일 카드 클릭은 실행
카드 배치를 확정하지 않는다.

## 6. DOTween 의존성 및 연출 생명주기

현재 프로젝트에는 DOTween이 없다. 공식 무료판 DOTween v1.3.030을 공식 배포본으로
`Assets/Plugins/Demigiant`에 추가한다. 가져온 뒤 `Tools > Demigiant > DOTween Utility Panel`에서
`Setup DOTween...`을 실행하고 asmdef를 생성해 `FateWeaver.Unity`가 명시적으로 참조하도록 한다.
버전과 라이선스 파일을 저장소에 함께 보존한다.

펄스는 실루엣의 `RectTransform.DOScale`을 사용한다.

- 목표 스케일: `Vector3.one * 1.06f`
- 편도 시간: `0.45f`초
- easing: `Ease.InOutSine`
- loop: `LoopType.Yoyo`, 무한 반복
- update: `SetUpdate(true)`로 게임 시간 배율과 독립
- 대상: 프리뷰 실루엣의 `GameObject`에 연결
- 종료: 숨김, 정적 전환, 카드 목록 갱신, 파괴 전에 tween을 kill
- 종료 후: `localScale = Vector3.one`으로 명시적 복원

전체 전역 tween을 정리하는 `DOTween.KillAll()`은 사용하지 않는다. 프리뷰가 소유한 `Tween` 참조만
종료해 향후 다른 연출과 간섭하지 않게 한다.

## 7. 데이터 흐름

```text
실행 카드 호버
  -> 무변이 자동 위치 계산
  -> HoverStatic 실루엣 표시

호버 종료(미선택)
  -> 실루엣 숨김

실행 카드 클릭
  -> 운명력/턴 검증
  -> CardSelectionMachine.ConfirmPlacement
  -> SelectedPulse 실루엣 고정

실루엣 클릭
  -> SelectionResult(대상 없음)
  -> DeckCombatSession.PlayExecutionCard(handIndex)
  -> 비용 차감 + 자동 정렬 배치
  -> tween/실루엣/선택 정리

조작 카드 클릭
  -> 기존 대상 선택/확인 흐름
```

## 8. 오류 및 정리

- 호버 인덱스가 손패 범위를 벗어나면 실루엣을 숨긴다.
- 호버 도중 카드 목록이 갱신되면 프리뷰를 먼저 정리한다.
- 선택 중 다른 실행 카드의 호버 이벤트는 현재 선택을 덮어쓰지 않는다.
- 운명력 부족, 해결된 턴, 카드 소실 또는 분류 변경은 실제 배치를 거부한다.
- 실제 배치 실패 후 유령 선택 상태를 유지하지 않는다.
- tween을 시작하기 전에 기존 tween을 종료하고 스케일을 복원한다.
- 비활성 실루엣은 레이아웃 공간과 입력을 차지하지 않는다.
- 조작 카드 선택 중에는 실행 카드 호버 프리뷰를 표시하지 않는다.

## 9. 검증

### 9.1 헤드리스 코어 테스트

- 실행 카드 배치 API가 대상 ID 없이 성공한다.
- 직접 대상이 필요한 기본 실행 카드가 세션 부팅 검증에서 거부된다.
- `Self`, 전체 아군, 위치 선택자와 자동 적 대상 실행 카드는 허용된다.
- 운명력이 부족한 실행 카드도 프리뷰 위치를 반환한다.
- 프리뷰는 상태 효과가 적용된 순서와 실제 삽입 위치를 반환한다.
- 프리뷰 호출 전후 에너지, 손패, 버림패, 미래 영역, 인스턴스 ID와 RNG가 변하지 않는다.
- 실제 배치는 프리뷰와 같은 정렬 규칙을 사용한다.
- 레거시 검증 카드가 `Self`로 변환됐는지 확인한다.

### 9.2 Unity EditMode 테스트

- 실행 카드 호버는 정적 실루엣을 자동 위치에 표시하고 뒤 카드를 민다.
- 호버 종료는 미선택 실루엣을 숨긴다.
- 조작 카드 호버는 실루엣을 표시하지 않는다.
- 손패 클릭 뒤 실루엣은 고정되고 입력 가능해진다.
- 손패 클릭 전 실루엣은 입력 불가능하다.
- 선택 상태에서 DOTween tween이 활성이고 호버 상태에서는 활성이지 않다.
- 숨김·취소·성공·목록 갱신에서 tween이 종료되고 스케일이 1로 돌아온다.
- 마우스 추적 전체 카드와 손패 반투명 고스트가 생성되지 않는다.
- 실루엣 클릭은 대상 없는 배치 결과를 한 번만 전송한다.
- 선택 중 기존 레일 카드 호버는 전체 카드 상세보기를 표시한다.
- 레일 배경과 기존 카드 클릭은 실루엣 대신 배치를 확정하지 않는다.
- 조작 카드 단일·다중 대상 선택과 확인 버튼 동작이 유지된다.

### 9.3 수동 플레이 검증

- 모든 실행 카드가 호버만으로 정적 자동 위치를 보여준다.
- 호버만 할 때 실루엣 크기는 변하지 않는다.
- 손패 카드 클릭 뒤 마우스 추적 카드 없이 실루엣만 반복 확대·축소한다.
- 실루엣 클릭 후 실제 카드가 같은 위치에 나타난다.
- 선택 중 기존 레일 카드의 상세보기를 열 수 있다.
- 빈 영역 취소, 운명력 부족, 턴 종료에서 tween과 실루엣이 남지 않는다.
- 조작 카드 선택 UX는 기존과 같다.
- Console에 tween 대상 소실 또는 중복 tween 오류가 없다.

## 10. 고려한 대안

- Unity `Update`와 `Mathf.Sin` 기반 펄스는 외부 의존성이 없지만, 향후 공통 연출 기반으로 DOTween을
  사용하려는 제품 방향과 맞지 않아 제외했다.
- Unity 컨트롤러에 별도 대상 선택 결과를 저장하는 방식은 실행 카드가 무대상으로 고정되면서 필요가
  없어졌다.
- 손패 클릭 즉시 배치는 자동 위치 확인과 두 단계 배치 의도를 약화하므로 제외했다.
- 레일 전체 클릭 배치는 어떤 카드가 확정되는지 모호하므로 실루엣 자체 클릭으로 제한한다.
