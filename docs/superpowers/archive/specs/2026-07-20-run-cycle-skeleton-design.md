## 0. 목표

전투 슬라이스 하나뿐인 현재 상태에서, **런(run) 하나가 시작부터 끝까지 닫히는 최소 사이클**을 만든다. 새 메커니즘·새 콘텐츠 저작은 최소화하고, 기존 캐릭터·적·카드를 재사용해 루프 구조 자체를 검증한다.

## 1. 확정된 결정

| 항목 | 결정 |
|---|---|
| 사이클 범위 | 최소 뼈대. 무작위 이벤트·상점 노드 제외 |
| 재화(골드) | 없음. 고용·회복 노드는 무료로 작동. 상점 도입 시 함께 도입 |
| 맵 | **고정 배열** 일직선. SO로 저작, 런 시드와 무관 |
| 노드 종류 | 일반 전투 / 엘리트 전투 / 보스 전투 / 고용·회복 |
| 전투 보상 | 승리 시 **3장 중 1장 선택, 스킵 가능**. 런 시드로 롤 |
| 카드 귀속 | party-foundation 규칙 준수 — 획득 시 소유 캐릭터 지정, 고유 카드는 보유 캐릭터가 있을 때만 등장(더 높은 비중), 범용 카드는 누구에게나 |
| HP | 전투 간 이월. 고용/회복 노드에서만 회복(회복량은 튜닝 데이터, 초안: 전원 전체 회복) |
| 고용 | 기본 키트로 합류. 경력 드래프트는 다음 사이클 |
| 엘리트/보스 | 기존 적의 스탯·인원 변주 인카운터. 신규 메커니즘 없음 |
| 승리/패배 | 보스 노드 클리어 = 승리, 전멸 = 패배. 결과 화면 → 새 런 |

## 2. 아키텍처 결정

**런 레이어도 코어(`FateWeaver.Core`)에 둔다.** 보상 롤·고용·HP 이월·승패 판정은 전부 게임 규칙이므로 순수 C# 코어에 두고, Unity는 맵 화면·씬 전환·보상 UI만 담당한다. (대안이었던 "Unity GameManager가 런 관리"는 규칙 6·7·12 위반으로 탈락.)

## 3. 코어 설계

### 3.1 RunState

런 하나의 영속 상태. 필드:

- 노드 목록(코어 데이터로 변환된 RunDefinition)과 현재 노드 인덱스
- 파티: 캐릭터별 현재/최대 HP + 소유 카드 목록 (합성 덱의 원천)
- 런 시드 RNG — 보상 롤 등 런 레벨 무작위 전용
- 런 결과: 진행 중 / 승리 / 패배

**시드 규칙:** 맵이 고정 배열이라도 보상 롤 때문에 런 시드는 존재한다. 각 전투의 전투 시드는 런 시드에서 파생시켜 "같은 런 시드 = 같은 전투 시드 열"을 보장한다. 규칙 7(결정론)에 따라 런 레이어의 모든 무작위는 이 RNG를 경유한다.

### 3.2 RunDefinition (데이터)

노드 배열. 각 노드 = **노드 종류 키 + 페이로드**:

- 전투 노드(일반/엘리트/보스): 인카운터 참조
- 고용/회복 노드: 고용 후보 캐릭터 참조, 회복량

Unity SO로 저작하고 로드 시 코어 데이터로 변환한다 — 기존 카드 SO 저작 파이프라인과 같은 패턴.

### 3.3 노드 진행 흐름

노드 종류별 처리는 기존 레지스트리 패턴(규칙 9)을 따라 **노드 타입 키 + 핸들러 등록**으로 구현한다. 중앙 switch를 만들지 않는다.

- **전투 노드:** `RunState` → `CombatState` 생성(파티 현재 HP·합성 덱 반영, 전투 시드는 런 시드에서 파생) → 전투 종료 → 생존자 HP·사망자를 `RunState`에 반영 → 승리 시 보상 롤.
- **고용/회복 노드:** 파티에 후보 캐릭터 합류(기본 키트, 최대 3인 미만일 때) + 회복 적용. 전투 없음.
- 노드 완료 → 다음 노드 인덱스로 전진. 보스 노드 클리어 = 승리, 전멸 = 패배.

### 3.4 보상 롤

승리한 전투 노드에서 런 시드로 카드 3장을 롤해 제시한다. 1장 선택 또는 스킵. 획득 카드는 party-foundation 규칙대로 소유 캐릭터에 귀속된다. 후보 수(3)·고유 카드 가중치는 튜닝 데이터로 둔다(규칙 8).

### 3.5 사망 처리

party-foundation 규칙을 따른다: 전투 중 사망 시 그 캐릭터의 카드는 덱·손패에서 즉시 제거, 미래 영역 배치분 무효화. 최소 뼈대에서는 **전투 후 카드 인계 없이 소멸만** 구현한다. 전멸 = 런 패배.

### 3.6 테스트 (헤드리스, 규칙 12)

1. **결정론 테스트:** 같은 RunDefinition + 같은 런 시드 = 같은 보상 롤, 같은 전투 시드 열, 같은 진행 결과.
2. **원 사이클 통합 테스트:** 기존 시뮬레이션 하니스로 전투를 자동 플레이해 맵 시작 → 보스 클리어(또는 전멸)까지 완주.

## 4. Unity 레이어

- **맵 화면:** 일직선 노드 아이콘 + 현재 위치 표시 + 다음 노드 진입 버튼. 프리팹 저작, 인스펙터 참조(규칙 1·2·3).
- **화면 흐름:** 맵 → (전투 씬 → 보상 3택1 화면) 또는 (고용/회복 화면) → 맵 → … → 결과 화면(승리/패배) → 새 런.
- **보상 화면:** 기존 카드 UI 재사용. 3장 제시 + 스킵 버튼.
- **고용/회복 화면:** 합류 확인 + 회복 적용 표시. 최소 UI.
- **결과 화면:** 승리/패배 표시 + 새 런 시작 버튼.
- `RunState`의 씬 간 유지 방식은 기존 패턴을 검색해 따른다(규칙 13). 문자열 탐색·경로 하드코딩 금지.

## 5. 콘텐츠 (SO 저작)

- **RunDefinition SO 1개** — 예시 배열: 일반 → 일반 → 고용/회복 → 일반 → 엘리트 → 고용/회복 → 보스. 노드 수·순서는 저작 데이터이므로 구현과 무관하게 조정 가능.
- **인카운터 SO** — 일반(고블린 조합) / 엘리트(간수 포함 조합) / 보스(기존 적 강화 변주) 각 1종 이상.
- **고용 후보** — 기존 member_b 기본 키트 재사용. 1인 시작 → 고용 노드에서 2인 (party-foundation §6의 2인 파티 검증과 정합).

## 6. 범위 외

무작위 이벤트 노드, 상점 노드, 재화, 카드 제거·강화, 사망 캐릭터 카드 인계, 경력 드래프트, 시드 맵 생성, 맵 분기, 런 중 저장/이어하기, 메타 프로그레션.
