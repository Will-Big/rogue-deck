실제 Unity 프리팹 캡처 · 5종 · 혼합 손패 · 960×720

실제 게임의 어두운 바탕에 밝은 글자색을 적용했습니다. 설명 문구는 원문을 그대로 사용하고 대상 제목만 별도로 표시합니다. 전체 JSON 카드의 본문 범위·긴 제목, 재바인딩, 상태·선택·뒷면, 네 화면비 손패를 자동 검증합니다.

의존 방향

카탈로그는 프리팹을 공급하고 CardView가 패널로 참조를 전달합니다. 게임 데이터는 읽기 전용 표시 입력으로 사용합니다. 본문 그룹은 원래 순서를 유지하고, 대상 띠만 목업의 적군 왼쪽·아군 오른쪽 순서로 표시합니다.

대안 · 기존 외형 유지

소비처 영향은 작지만 내부 영역이 압축됩니다. 사용자 크기 선택에 따라 두 문서를 함께 갱신합니다.

나중에 어려워지는 것

  • 더 긴 카드와 안쪽 비용은 손패가 겹칠 때 가독성에 영향을 줍니다. 실제 화면비와 hover 캡처가 필요합니다.
  • 고정 크기에 임의 길이 설명을 무한히 넣을 수 없습니다. 최소 글꼴 크기에서도 넘치는 현행 카드는 ID와 캡처로 검토하며 문장을 숨기지 않습니다.
  • 모두의 여러 칸이 고정 인원수로 보일 수 있습니다. 괄호와 대상 제목을 함께 검수합니다.
  • 직렬화 참조를 분리하므로 기존 테스트 fixture와 모든 프리팹 배선을 함께 바꿔야 합니다.

  1. CardView.Bind가 표시 스냅샷을 받습니다.
  2. 대상 띠는 적군/모두와 아군/자신을 두 칸과 세로선으로 표시합니다.
  3. 설명 패널은 입력 순서대로 두 그룹을 만들고 두 번째 그룹 위에 가로선을 둡니다.
  4. 각 그룹은 대상 제목을 상단에 고정하고 본문을 원문 그대로 표시합니다.
  5. 같은 카드가 아군/자신 한 그룹으로 다시 Bind되면 이전 적군 영역을 없애고, 대상 기호는 중앙·본문은 세로 중앙 왼쪽 정렬로 바뀝니다.

구현 순서와 검증

  1. 설명 그룹: 제목/본문 분리, null·빈 목록·긴 문구·재Bind 테스트.
  2. 대상 띠: 단일/복합 분할, 모두·자신 기호, 기존 전방/후방 방향 유지.
  3. 전체 카드: 프리팹 배선, 소유자 수정, 기존 상태·뒷면·입력 회귀.
  4. 소비처: 손패·레일 확대 크기 일치, 화면비별 렌더 캡처와 사용자 Play.

전체 Tools/verify.sh, Unity EditMode, 관련 PlayMode, 별도 Explicit 렌더 캡처를 실행합니다. 자동화는 참조·텍스트·bounds·상태 전이를 확인하고, 사용자가 최종 모양과 Play를 확인합니다. master 머지는 별도 승인 후 진행합니다.

기존 소비처 근거: HandFanView.SetCards, ExecutionRailView.OnHover. 문서·검수 절차: 문서 형식, Unity 배치 검증.
