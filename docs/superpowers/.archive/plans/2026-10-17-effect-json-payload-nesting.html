효과·조작 JSON 페이로드 중첩 — 구현 계획

2026-10-17 · 계획 검토 대기 · 승인된 설계: 효과 JSON 페이로드 중첩

승인된 설계를 다섯 태스크로 나눠 구현한다. 각 태스크는 끝에서 Tools/verify.sh가 통과해야 커밋한다. 세션 인계용 상세

무엇을 하나

순서는 "작고 닫힌 변경부터"다. 먼저 동작만 바꾸고(형식 그대로), 다음에 형식 버전을 없애고, 마지막에 이름·구조를 바꾼다. 그래서 어느 태스크에서 멈춰도 저장소는 통과하는 상태다.

새 테스트는 쓰지 않는다(사용자 결정). 기존 테스트는 고치고, 폐지된 기능(형식 버전·구형 변환)만 검증하던 테스트 7개는 지운다. 테스트가 잡지 않는 위험 5가지는 태스크 안의 수동 확인 단계로 본다.

태스크

태스크바뀌는 것JSON끝난 뒤 상태
1. consume_status 개수 이동코어 페이로드에서 Amount 제거, 핸들러·검증·설명이 EffectValue를 읽음그대로소비 개수에 성공 수치·scaling이 적용됨
2. 형식 버전 제거CardFormatMigration·CardFormat·형식 검사 삭제cardFormat 줄 삭제(35장)카드는 형식 버전 없음
3. 효과 이름·중첩효과 스펙 7개, 페이로드 스펙 4개 신설, 컨버터 key효과 47줄 재작성(31장)효과 JSON = EffectData 모양
4. 조작 이름·중첩조작 스펙 2개, 페이로드 스펙 2개 신설, 컨버터 key조작 4장 재작성조작 JSON = InterventionActionData 모양
5. 도구·문서카드 그래프 추출기, 저작 규칙 문서, 대체된 설계 2개 머리말, 색인—설계 current, 계획 보관

순서와 의존

대안과 기각 이유

기각: 한 커밋에 전부 바꾼다. 콘텐츠 35장과 테스트 25개 파일이 한꺼번에 바뀌면 실패 원인을 가리기 어렵다. 태스크 1·2는 형식 이름을 건드리지 않아 따로 검증된다.

기각: 콘텐츠를 C# 직렬화기로 다시 쓴다. 새 스펙은 옛 JSON을 읽지 못하므로(옛 이름은 거부) 직렬화기로 왕복할 수 없다. 일회성 파이썬 변환으로 다시 쓰고, 바이트 비교 테스트(Repository_cards_round_trip_byte_identically)로 직렬화기와 같은 모양인지 확인한다. 파이썬 json.dumps(indent=2, ensure_ascii=False)는 현재 35장과 바이트가 같다(2026-10-17 확인).

이 계획으로 나중에 어려워지는 것

  • 새 테스트가 없어서, 소비 개수에 성공 수치·scaling이 적용되는 새 동작과 Review Focus 5가지는 수동 확인 단계로만 확인된다. 다음 사람이 같은 확인을 반복하려면 계획을 다시 읽어야 한다.
  • 테스트 수정 범위가 컴파일 오류에 따라 정해진다(후보 25개 파일). 형식 없는 인라인 JSON이 예전에 구형 변환에 기대어 통과했다면, 태스크 2에서 그 JSON을 현재 형식으로 손으로 고쳐야 한다.
  • 카드 그래프 추출기의 효과 단위 condition 경고와 그 테스트 2개를 지운다(현재 형식에 없는 필드). 그래프에서 조건 정보는 계속 빠진다.
