# Fate Weaver — 카드 아이디어 노트 설계

- 작성일: 2026-07-27
- 문서 유형: `tool-design`
- 주 도메인: `card-ideation`
- 하위 유형: `static-web-tool`, `markdown-export`, `local-draft`
- 관련 규칙:
  [위치 대상과 카드 텍스트 설계](2026-07-27-position-targeting-card-text-design.md)
- 상태: `current` — 단일 HTML 도구 구현 완료
- 범위: 게임 데이터와 분리된 카드 초안 편집, 브라우저 로컬 저장, AI 전달용 Markdown 내보내기

## 1. 목적

카드 아이디어를 떠올린 즉시 브라우저의 입력 UI에서 정리하고, 후속 AI가 읽어 Unity에서 사용 가능한
카드 에셋으로 저작할 수 있는 Markdown 파일로 내보낸다.

이 도구는 게임 데이터 편집기가 아니다. `CardAsset`, `EffectSpec`, 효과 키, 핸들러 레지스트리,
ScriptableObject와 직접 연결하지 않는다. 카드 능력은 구현 가능성에 제한받지 않는 자유 문장으로
작성한다.

기본 사용 흐름은 다음과 같다.

```text
브라우저에서 카드 초안 작성
  → 명시적으로 로컬 저장
  → 저장된 카드 중 AI에게 전달할 카드 선택
  → 하나의 Markdown 파일로 내보내기
  → 사용자가 파일을 작업공간에 놓고 AI에게 경로 전달
  → AI가 현행 규칙과 구현 구조를 확인한 뒤 Unity 카드로 저작
```

## 2. 기술 형태

도구는 `Tools/card-idea-notebook/index.html` 하나로 완결되는 정적 웹 페이지다.

- HTML, CSS, vanilla JavaScript만 사용한다.
- 마크업, 스타일, 동작 코드를 모두 `index.html` 안에 포함한다.
- 외부 프레임워크와 패키지를 추가하지 않는다.
- 빌드 과정과 서버를 요구하지 않는다.
- 브라우저에서 `index.html`을 직접 열어 사용할 수 있어야 한다.
- 초안은 현재 브라우저의 `localStorage`에만 저장한다.
- AI 전달 파일은 브라우저의 `Blob` 다운로드로 생성한다.

브라우저 로컬 저장은 다른 브라우저나 기기와 동기화되지 않는다. Markdown 내보내기는 백업이자 AI 전달
경계이며, 도구가 저장소나 Unity 프로젝트 파일을 직접 수정하지 않는다.

구현 동작은 같은 디렉터리의 `index.test.mjs`에서 Node 기본 테스트 러너로 검증한다. 테스트 파일은
개발 검증용이며 사용자는 `index.html`만 열면 된다.

## 3. 화면 구조

화면은 데스크톱 브라우저를 기준으로 한 3열 카드 노트다.

```text
[저장된 카드 목록] [카드 편집 폼] [Markdown 원문 미리보기]
```

### 3.1 저장된 카드 목록

- 새 카드
- 이름·태그 검색
- 저장된 카드 선택
- Markdown 내보내기 대상 체크
- 카드 복제
- 카드 삭제

목록은 저장된 값만 보여준다. 현재 편집 폼에 저장하지 않은 변경이 있어도 목록의 카드 이름과 태그를
몰래 바꾸지 않는다.

### 3.2 카드 편집 폼

폼은 카드 한 장의 현재 편집 버전을 보여준다. 저장된 버전과 다르면 `저장되지 않은 변경` 상태를
명확히 표시한다.

### 3.3 Markdown 원문 미리보기

현재 편집 폼을 Markdown 원문으로 즉시 보여준다. 이는 사용자가 생성 결과를 확인하기 위한 미리보기이며
클립보드 복사 버튼은 제공하지 않는다. AI용 파일 내보내기에는 저장된 카드 버전만 사용한다.

## 4. 카드 입력 항목

### 4.1 기본 정보

| 항목 | 형식 | 규칙 |
|---|---|---|
| 카드 이름 | 한 줄 텍스트 | 저장과 내보내기에 필수 |
| 역할 | `미정`, `실행`, `조작` | 기본값 `미정` |
| 비용 | 선택 숫자 | 비어 있으면 Markdown에서 생략 |
| 실행순서 | 선택 숫자 | 역할이 `실행`일 때만 표시 |
| 태그 | 자유 태그 목록 | 이름과 함께 목록 검색에 사용 |

역할의 의미를 도구가 검증하지 않는다. 아직 역할이 정해지지 않은 아이디어는 `미정`으로 저장할 수 있다.

### 4.2 진영별 위치 범위

아군과 적군은 서로 독립적으로 다음 값을 선택한다.

- 없음
- 앞 하나
- 앞 둘
- 뒤 하나
- 뒤 둘
- 모두

위치 범위의 의미와 방향은
[위치 대상과 카드 텍스트 설계](2026-07-27-position-targeting-card-text-design.md)를 따른다. 편집 UI와
Markdown 미리보기에서 아군과 적군의 전열은 서로 마주보게 표시한다.

### 4.3 능력 문장

다음 세 영역을 자유로운 여러 줄 텍스트로 입력한다.

- 적군 능력
- 아군 능력
- 대상 없는 능력

도구는 `피해`, `방어`, `독`, `드로우` 같은 효과 목록이나 수치 필드를 강제하지 않는다. 한 줄을 하나의
능력 문장으로 취급해 Markdown 목록 항목으로 출력한다.

### 4.4 설계 메모

설계 의도, 미정 수치, 연계 후보와 남은 고민을 자유 문장으로 기록한다. 빈 메모는 Markdown에서
생략한다.

## 5. 위치 범위 표기

도구의 위치 표기는 실제 유닛 수가 아니라 위치 범위를 나타낸다.

| 위치 범위 | 아군 | 적군 |
|---|---|---|
| 앞 하나 | `━━━━◆` | `◆━━━━` |
| 앞 둘 | `━━━◆◆` | `◆◆━━━` |
| 뒤 하나 | `◆━━━━` | `━━━━◆` |
| 뒤 둘 | `◆◆━━━` | `━━━◆◆` |
| 모두 | `━━━━━` | `━━━━━` |

한 진영만 사용하는 카드는 그 진영만 표시하고, 양 진영을 사용하면 한 줄에서 마주보게 표시한다. 두
진영 모두 `없음`이면 대상은 `없음`으로 출력한다.

## 6. 명시적 저장

입력 변경은 자동 저장하지 않는다.

- `저장` 버튼이나 `Ctrl+S`·`Cmd+S`를 사용해야 `localStorage`에 반영한다.
- 저장 후 입력이 달라지면 `저장되지 않은 변경`을 표시한다.
- 새 카드와 복제한 카드는 저장 전까지 임시 편집 상태다.
- 저장하지 않은 상태에서 브라우저를 닫거나 새로고침하면 브라우저 경고를 표시한다.
- 저장하지 않은 내용을 별도의 복구 초안으로 몰래 보존하지 않는다.

저장하지 않은 변경이 있는 상태에서 다른 카드를 선택하거나 새 카드를 만들거나 복제·삭제하려 하면
다음 선택을 제공한다.

1. 저장
2. 변경 버리기
3. 취소

카드 삭제는 별도의 확인을 거친다.

## 7. 로컬 저장 모델

저장 루트는 스키마 버전을 가진다.

```text
schemaVersion
cards[]
activeCardId
searchQuery
exportSelection[]
```

각 카드는 사용자에게 보이지 않는 내부 식별자와 다음 데이터를 가진다.

```text
id
name
role
cost
executionOrder
tags[]
targets.ally
targets.enemy
abilities.ally[]
abilities.enemy[]
abilities.none[]
notes
createdAt
updatedAt
```

스키마 버전은 이후 필드가 늘어날 때 기존 로컬 초안을 명시적으로 변환하거나 안전하게 거부하기 위한
값이다. 알 수 없는 버전을 현재 구조로 조용히 덮어쓰지 않는다.

## 8. 검증

아이디어 단계의 미완성을 허용하기 위해 대부분의 문제는 경고로 표시하며 내보내기를 막지 않는다.

### 8.1 차단 오류

- 저장하려는 카드 이름이 비어 있음
- Markdown으로 내보낼 저장 카드가 선택되지 않음

### 8.2 경고

- 진영 능력은 있지만 해당 진영 위치 범위가 `없음`
- 진영 위치 범위는 있지만 해당 진영 능력이 비어 있음
- 역할이 `실행`이지만 실행순서가 비어 있음
- 비용이 비어 있음

경고는 카드 목록과 편집 폼에서 확인할 수 있다. 경고가 있는 저장 카드도 사용자가 선택하면 Markdown으로
내보낼 수 있다.

## 9. Markdown 생성

### 9.1 카드 한 장

빈 기본 정보, 빈 능력 묶음과 빈 메모 절은 출력하지 않는다.

```markdown
## 맹독 찌르기

- 역할: 실행
- 비용: 1
- 실행순서: 4
- 태그: 독, 성장
- 대상: 아군 뒤 하나 `◆━━━━` │ `◆◆━━━` 적군 앞 둘

### 능력

- [적군] 피해를 주고 독을 부여한다.
- [아군] 방어를 부여한다.
- 카드 한 장을 뽑는다.

### 메모

독 성장과 방어를 동시에 제공하는 초안.
수치는 아직 결정하지 않음.
```

대상 능력이 전혀 없으면 `- 대상: 없음`을 출력한다. 적군·아군 능력에는 진영 표기를 붙이고 대상 없는
능력에는 진영 표기를 붙이지 않는다. 위치 그림과 위치 범위 이름을 함께 남겨 사람이 읽을 때와 AI가
해석할 때 모두 의미가 보존되게 한다.

### 9.2 여러 카드 묶음

저장 목록에서 체크한 카드들을 하나의 파일로 내보낸다. 한 장만 선택하는 것도 허용한다.

```markdown
# Fate Weaver 카드 아이디어

- 생성일: 2026-07-27
- 카드 수: 2
- 대상 규칙: `docs/superpowers/specs/2026-07-27-position-targeting-card-text-design.md`

## 첫 번째 카드

...

## 두 번째 카드

...
```

파일명은 날짜를 포함한 `fate-weaver-card-ideas-YYYY-MM-DD.md`를 기본값으로 한다. 내보내기 버튼의
이름은 `AI용 Markdown 내보내기`다.

현재 편집 카드가 내보내기 대상으로 선택되어 있고 저장되지 않은 변경이 있으면 다음 선택만 제공한다.

1. 저장 후 내보내기
2. 내보내기 취소

이전 저장본이나 화면의 미저장 버전을 사용자에게 알리지 않고 내보내지 않는다.

## 10. 구성 요소

구현은 역할을 다음처럼 분리한다.

- 카드 모델 정규화와 비교
- 검증과 경고 생성
- 위치 범위와 Markdown 생성
- `localStorage` 저장소와 스키마 검사
- 목록 선택·검색·복제·삭제
- 편집 폼과 미저장 변경 보호
- 선택 카드 Markdown 다운로드

순수 데이터 변환과 검증은 DOM 조작에서 분리해 브라우저를 열지 않고도 테스트할 수 있어야 한다.

## 11. 검증 전략

### 자동 검증

- 위치 범위별 아군·적군 Markdown 표기
- 한쪽·양쪽·대상 없음 조합
- 빈 선택 항목 생략
- 여러 줄 능력의 진영별 목록 생성
- 여러 카드 묶음과 생성 정보
- 검증 오류와 경고 구분
- 저장 전후 변경 감지
- 현재 스키마 직렬화·역직렬화와 알 수 없는 버전 거부

### 브라우저 검증

- 새 카드, 저장, 다시 불러오기
- 미저장 상태에서 카드 전환·새로고침 경고
- 복제와 삭제 확인
- 이름·태그 검색
- 내보내기 카드 체크와 Markdown 다운로드
- 좁아진 창에서도 주요 입력과 Markdown을 사용할 수 있는지

## 12. 범위 밖

- 카드 이미지와 실제 게임 카드 프레임 미리보기
- Unity, ScriptableObject 또는 게임 코드 직접 수정
- 효과 키·상태 키·핸들러 구현 가능성 검증
- Markdown 파일을 저장소에 직접 쓰는 로컬 서버
- 클립보드 복사
- 계정, 클라우드 저장과 기기 간 동기화
- Markdown 재가져오기
- 모바일 전용 UI
