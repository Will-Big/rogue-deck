# Fate Weaver — 카드 아이디어 노트 설계

- 작성일: 2026-07-27
- 개정일: 2026-07-28
- 문서 유형: `tool-design`
- 주 도메인: `card-ideation`
- 하위 유형: `static-web-tool`, `markdown-import-export`, `auto-preserved-draft`
- 관련 규칙:
  [위치 대상과 카드 텍스트 설계](2026-07-27-position-targeting-card-text-design.md)
- 상태: `current` — 카드 진영과 명시적 개별·전체 저장 개정 승인, 구현 전
- 범위: 게임 데이터와 분리된 카드 초안 편집, 브라우저 즉시 보존, 완성 상태 관리,
  아군·적군 카드 분기, 공용 카드 선택·일괄 삭제, 카드 순서 저작,
  AI 전달용 Markdown 불러오기·내보내기

## 1. 목적

카드 아이디어를 떠올린 즉시 브라우저의 입력 UI에서 정리하고, 후속 AI가 읽어 Unity에서 사용 가능한
카드 에셋으로 저작할 수 있는 Markdown 파일로 내보낸다.

이 도구는 게임 데이터 편집기가 아니다. `CardAsset`, `EffectSpec`, 효과 키, 핸들러 레지스트리,
ScriptableObject와 직접 연결하지 않는다. 카드 능력은 구현 가능성에 제한받지 않는 자유 문장으로
작성한다.

기본 사용 흐름은 다음과 같다.

```text
브라우저에서 카드 초안 작성
  → 입력 즉시 브라우저에 보존
  → 현재 카드 또는 전체 카드를 명시적으로 저장해 완성 조건 재판정
  → 완성 카드 중 AI에게 전달할 카드 선택
  → 필요하면 카드 목록 순서와 내보낼 파일명 조정
  → 하나의 Markdown 파일로 내보내기
  → 필요하면 같은 형식의 Markdown 파일을 다시 불러오기
  → 사용자가 파일을 작업공간에 놓고 AI에게 경로 전달
  → AI가 현행 규칙과 구현 구조를 확인한 뒤 Unity 카드로 저작
```

## 2. 기술 형태

도구는 `Tools/card-idea-notebook/index.html` 하나로 완결되는 정적 웹 페이지다.

- HTML, CSS, vanilla JavaScript만 사용한다.
- 마크업, 스타일, 동작 코드를 모두 `index.html` 안에 포함한다.
- 외부 프레임워크와 패키지를 추가하지 않는다.
- 빌드 과정과 서버를 요구하지 않는다.
- 브라우저에서 `index.html`을 직접 열어 사용할 수 있어야 한다.
- 초안은 현재 브라우저의 `localStorage`에만 저장한다.
- AI 전달 파일은 브라우저의 `Blob` 다운로드로 생성하고, 같은 형식의 `.md` 파일을 브라우저에서
  다시 읽을 수 있다.

브라우저 로컬 저장은 다른 브라우저나 기기와 동기화되지 않는다. Markdown 내보내기는 백업이자 AI 전달
경계이며, 도구가 저장소나 Unity 프로젝트 파일을 직접 수정하지 않는다.

구현 동작은 같은 디렉터리의 `index.test.mjs`에서 Node 기본 테스트 러너로 검증한다. 테스트 파일은
개발 검증용이며 사용자는 `index.html`만 열면 된다.

## 3. 화면 구조

화면은 데스크톱 브라우저를 기준으로 한 3열 카드 노트다.

```text
[카드 목록] [카드 편집 폼] [Markdown 원문 미리보기]
```

### 3.1 카드 목록

- 새 카드
- 이름·태그 검색
- 완성·미완성 상태 표시
- 아군·적군 진영 표시
- 완성·미완성 공용 카드 선택
- 모든 카드 전체 체크·전체 해제
- 전용 손잡이를 사용한 카드 순서 변경
- Markdown 불러오기
- 카드 복제
- 선택 카드 일괄 삭제
- 기본 내보내기 파일명 입력

완성 카드와 미완성 카드를 하나의 `cards[]` 목록에 표시한다. 새 카드를 누르면 고유 ID를 가진
`새 카드`가 즉시 목록에 생기며, 같은 이름이 이미 있으면 `새 카드 (2)`, `새 카드 (3)`처럼 번호를
붙인다. 카드 이름과 태그를 편집하면 즉시 보존된 현재 값이 목록에도 반영된다.

카드 목록 열은 위쪽의 스크롤 영역과 아래쪽의 작업 영역으로 나눈다. 검색·전체 체크·카드 목록은
스크롤 영역 안에 두고, 기본 파일명 입력과 `복제`, `삭제`, `Markdown 불러오기`,
`Markdown 내보내기`는 별도 작업 영역에 둔다. 작업 영역은 목록 위에 겹치지 않고 자체 높이만큼
공간을 차지하므로 마지막 카드도 가려지지 않은 채 스크롤할 수 있어야 한다.

각 카드의 체크박스는 삭제와 내보내기가 함께 사용하는 공용 선택이다. 미완성 카드도 선택할 수 있다.
`전체 체크`는 현재 검색 결과와 관계없이 모든 카드를 선택하거나 해제한다. 체크된 카드가 하나 이상인
상태에서 `삭제`를 누르면 체크된 카드만 일괄 삭제한다. 아무 카드도 체크하지 않았다면 현재 열어 둔
카드 한 장을 삭제하는 기존 동작을 유지한다. 한 장을 삭제할 때는 확인창에 카드 이름을 표시하고,
여러 장을 삭제할 때는 삭제할 카드 수를 표시한다. 활성 카드가 삭제 대상이 아니면 그대로 유지한다.
활성 카드가 삭제되면 남은 첫 카드를 열고, 남은 카드가 없으면 편집 폼을 비운다.

각 카드 행은 체크박스와 카드 열기 버튼에 영향을 주지 않는 전용 드래그 손잡이 `⠿`를 가진다.
손잡이에서 드래그를 시작하고 다른 카드의 위쪽 절반에 놓으면 그 카드 앞으로, 아래쪽 절반에 놓으면
그 카드 뒤로 삽입한다. 사이의 카드는 한 칸씩 이동하며 두 카드의 자리만 맞바꾸지 않는다. 드래그
중인 카드와 삽입 위치는 시각적으로 구분한다. 검색어가 입력된 동안에는 일부 카드만 보이는 상태에서
전체 순서가 바뀌는 혼동을 막기 위해 손잡이를 비활성화하고
`검색 중에는 순서를 변경할 수 없습니다.`를 안내한다.

### 3.2 카드 편집 폼

폼은 카드 한 장의 현재 편집 버전을 보여준다. 모든 입력은 초안 유실 방지를 위해 즉시 보존된다.
오른쪽 위에는 `저장`과 `전체 저장` 버튼을 나란히 둔다. `저장`은 현재 카드, `전체 저장`은 목록의
모든 카드에 완성 조건을 적용해 각각 `완성` 또는 `미완성`으로 다시 판정한다. 빈 핵심 정보가 있는
카드를 저장해도 값을 버리거나 완성으로 강제하지 않는다. 완성 카드를 다시 편집하면 즉시 `미완성`
상태로 돌아간다.

`Ctrl+S`와 `Cmd+S`는 현재 카드 저장, `Ctrl+Shift+S`와 `Cmd+Shift+S`는 전체 저장이다. 입력이나
메모를 편집 중이어도 동작하며 브라우저의 기본 페이지 저장 동작은 막는다.

### 3.3 Markdown 원문 미리보기

현재 편집 폼을 Markdown 원문으로 즉시 보여준다. 이는 사용자가 생성 결과를 확인하기 위한 미리보기이며
클립보드 복사 버튼은 제공하지 않는다. Markdown 파일 내보내기에는 사용자가 체크한 카드가 모두 완성
상태일 때만 그 카드들을 사용한다.

## 4. 카드 입력 항목

### 4.1 기본 정보

| 항목 | 형식 | 규칙 |
|---|---|---|
| 카드 이름 | 한 줄 텍스트 | 완성 판정과 내보내기에 필수 |
| 진영 | `아군`, `적군` | 새 카드와 기존 카드의 기본값 `아군` |
| 비용 | 아군은 숫자, 적군은 `없음` | 적군에서는 표시하되 편집 비활성화 |
| 역할 | 아군은 `미정`, `실행`, `조작`; 적군은 `실행` | 적군에서는 표시하되 편집 비활성화 |
| 실행순서 | 숫자 | 모든 실행 카드의 완성 조건 |
| 태그 | 자유 태그 목록 | 이름과 함께 목록 검색에 사용 |

아군 카드는 비용을 입력하고 역할을 `실행` 또는 `조작`으로 정해야 완성된다. 적군을 선택하면 비용을
`없음`, 역할을 `실행`으로 고정한다. 다시 아군으로 바꾸면 비용은 빈칸, 역할은 `미정`으로 초기화한다.
적군 비용의 저장값은 빈 문자열이며 진영으로 비용 없음의 의미를 판정한다. UI와 Markdown에서는
`없음`으로 표시한다.

핵심 정보는 카드 이름, 진영, 아군 비용, 아군 역할, 실행 카드의 실행순서다. 태그·위치 범위·능력·메모는
비어 있어도 완성할 수 있다.

### 4.2 진영별 위치 범위

아군과 적군은 서로 독립적으로 다음 값을 선택한다.

- 없음
- 자신
- 앞 하나
- 앞 둘
- 뒤 하나
- 뒤 둘
- 모두

`자신`은 플레이어 캐릭터의 카드에서는 아군 현재 사용자를, 적의 실행 카드에서는 적군 현재 사용자를
뜻한다. 한 카드에서 양 진영을 모두 `자신`으로 지정할 수는 없다.

위치 범위의 의미와 방향은
[위치 대상과 카드 텍스트 설계](2026-07-27-position-targeting-card-text-design.md)를 따른다. 편집 UI와
Markdown 미리보기에서 아군과 적군의 전열은 서로 마주보게 표시한다.

### 4.3 능력 문장

다음 세 영역을 자유로운 여러 줄 텍스트로 입력한다.

- 적군 능력
- 아군 능력
- 대상 없는 능력

도구는 `피해`, `방어`, `독`, `드로우` 같은 효과 목록이나 수치 필드를 강제하지 않는다. 한 줄을 하나의
능력 문장으로 취급해 Markdown 목록 항목으로 출력한다.

### 4.4 설계 메모

설계 의도, 미정 수치, 연계 후보와 남은 고민을 자유 문장으로 기록한다. 빈 메모는 Markdown에서
생략한다.

## 5. 위치 범위 표기

도구의 위치 표기는 실제 유닛 수가 아니라 위치 범위를 나타낸다.

| 위치 범위 | 아군 | 적군 |
|---|---|---|
| 자신 | `◎` | `◎` |
| 앞 하나 | `━━━━◆` | `◆━━━━` |
| 앞 둘 | `━━━◆◆` | `◆◆━━━` |
| 뒤 하나 | `◆━━━━` | `━━━━◆` |
| 뒤 둘 | `◆◆━━━` | `━━━◆◆` |
| 모두 | `━━━━━` | `━━━━━` |

한 진영만 사용하는 카드는 그 진영만 표시하고, 양 진영을 사용하면 한 줄에서 마주보게 표시한다. 두
진영 모두 `없음`이면 대상은 `없음`으로 출력한다. `자신`은 레일 없이 `◎`만 표시하고 Markdown에는
`아군 자신` 또는 `적군 자신`이라는 범위 이름과 `◎` 마커를 함께 남긴다.

## 6. 즉시 보존과 완성 상태

모든 카드는 `complete` 또는 `incomplete` 상태를 가진다.

- 새 카드와 복제 카드는 생성 즉시 `incomplete`로 `cards[]`에 추가하고 `localStorage`에 보존한다.
- 입력이 바뀔 때마다 현재 카드 값을 즉시 `localStorage`에 반영한다.
- 다른 카드 선택, 새 카드 생성과 브라우저 새로고침 전에 별도의 저장 확인을 요구하지 않는다.
- `저장` 버튼과 `Ctrl+S`·`Cmd+S`는 현재 카드의 핵심 정보를 판정해 `complete` 또는 `incomplete`로
  저장한다.
- `전체 저장` 버튼과 `Ctrl+Shift+S`·`Cmd+Shift+S`는 모든 카드의 완성 상태를 한 번에 다시 판정한다.
- 전체 저장은 활성 카드, 공용 선택, 검색어와 카드 목록 순서를 바꾸지 않는다.
- 완성 카드의 저작 필드를 수정하면 즉시 `incomplete`로 바꾸고 보존한다.
- 검색어, 활성 카드와 공용 선택 변경은 카드 완성 상태를 바꾸지 않는다.
- 기본 파일명과 카드 목록 순서 변경은 카드 완성 상태를 바꾸지 않는다.
- 완성 카드가 편집으로 미완성 상태가 되어도 공용 선택은 유지한다.
- 단일 삭제와 선택 카드 일괄 삭제는 모두 별도의 확인을 거친다.

`localStorage` 쓰기가 실패하면 메모리의 현재 카드 목록은 유지한다. 화면에 `보존 실패`를 지속적으로
표시하고 이후 변경 때 전체 상태 저장을 다시 시도한다. 실패 상태에서 브라우저를 닫거나 새로고침하면
데이터 유실 가능성을 알리는 브라우저 경고를 표시한다. 저장소가 복구되어 전체 상태 쓰기에 성공하면
경고 상태를 해제한다.

## 7. 로컬 저장 모델

저장 루트는 스키마 버전을 가진다.

```text
schemaVersion
cards[]
activeCardId
searchQuery
selection[]
exportFileName
```

각 카드는 사용자에게 보이지 않는 내부 식별자와 다음 데이터를 가진다.

```text
id
name
faction
role
cost
executionOrder
tags[]
targets.ally
targets.enemy
abilities.ally[]
abilities.enemy[]
abilities.none[]
notes
completionStatus
createdAt
updatedAt
```

활성 편집본을 별도 `draft` 객체로 두지 않는다. `activeCardId`가 가리키는 `cards[]` 항목이 곧 편집
대상이며, 입력은 그 항목을 직접 갱신한 새 상태로 보존한다.

`selection[]`은 삭제와 내보내기가 함께 사용하는 선택 카드 ID 목록이다. 완성 상태와 관계없이 존재하는
카드 ID를 보존한다.

`cards[]`의 배열 순서가 카드 목록의 영구 순서다. 순서 변경은 배열만 재배열하고 `activeCardId`와
`selection[]`은 그대로 유지한다. 로컬 저장과 Markdown 묶음은 같은 배열 순서를 사용한다.

`exportFileName`은 카드 목록 아래에서 입력하는 기본 내보내기 파일명이다. 입력할 때 즉시 보존하고
새로고침 후 복원한다. 내보내기 대화상자에서 일회성으로 고친 이름은 이 필드에 반영하지 않는다.

스키마 버전은 이후 필드가 늘어날 때 기존 로컬 초안을 명시적으로 변환하거나 안전하게 거부하기 위한
값이다. 이 개정의 스키마 버전은 `5`다. 스키마 `1`의 `cards[]`는 우선 기존 규칙대로 `complete`로
변환하고, 스키마 `1`·`2`의 `exportSelection[]`은 `selection[]`으로 변환한다. 스키마 `1`~`3`에는
없던 `exportFileName`을 빈 문자열로 채운다.

스키마 `1`~`4`의 모든 카드는 `faction: "ally"`를 추가한 뒤 새 핵심 정보 규칙으로 완성 상태를 다시
판정한다. 따라서 비용·역할·실행순서가 빠진 기존 완성 카드는 값과 선택 상태를 유지한 채
`incomplete`가 된다. 기존 `cards[]` 배열 순서와 카드·선택·활성 카드·검색어를 그대로 보존하며,
알 수 없는 버전을 현재 구조로 조용히 덮어쓰지 않는다.

두 진영 모두 `자신`인 카드를 허용하지 않는 기존 규칙은 스키마 `5`에서도 유지한다.

## 8. 검증

아이디어 단계의 미완성을 허용한다. `incomplete` 카드는 로컬에서 계속 편집할 수 있지만 내보낼 수
없다. 저장은 빈 핵심 정보를 오류나 경고로 나열하지 않고 완성 상태에만 반영한다.

현재 카드와 전체 카드의 완성 판정은 같은 순수 규칙을 사용한다.

- 이름과 유효한 진영이 필요하다.
- 아군은 숫자 비용과 `실행` 또는 `조작` 역할이 필요하다.
- 적군은 비용 조건이 없고 역할을 `실행`으로 고정한다.
- 역할이 `실행`이면 진영과 관계없이 실행순서가 필요하다.
- 태그·위치 범위·능력·메모는 완성 조건이 아니다.

### 8.1 차단 오류

- Markdown으로 내보낼 카드가 선택되지 않음
- Markdown 내보내기 선택에 미완성 카드가 하나 이상 포함됨
- 불러올 Markdown의 묶음 또는 카드 형식이 올바르지 않음
- 아군과 적군 위치 범위가 모두 `자신`임

### 8.2 경고

- 진영 능력은 있지만 해당 진영 위치 범위가 `없음`
- 진영 위치 범위는 있지만 해당 진영 능력이 비어 있음

경고는 카드 목록과 편집 폼에서 확인할 수 있다. 빈 핵심 정보는 별도 경고 없이 `미완성` 배지로만
표현한다.

## 9. Markdown 생성

### 9.1 카드 한 장

빈 기본 정보, 빈 능력 묶음과 빈 메모 절은 출력하지 않는다.

```markdown
## 맹독 찌르기

- 진영: 아군
- 비용: 1
- 역할: 실행
- 실행순서: 4
- 태그: 독, 성장
- 대상: 아군 뒤 하나 `◆━━━━` │ `◆◆━━━` 적군 앞 둘

### 능력

- [적군] 피해를 주고 독을 부여한다.
- [아군] 방어를 부여한다.
- 카드 한 장을 뽑는다.

### 메모

독 성장과 방어를 동시에 제공하는 초안.
수치는 아직 결정하지 않음.
```

대상 능력이 전혀 없으면 `- 대상: 없음`을 출력한다. 적군·아군 능력에는 진영 표기를 붙이고 대상 없는
능력에는 진영 표기를 붙이지 않는다. 위치 그림과 위치 범위 이름을 함께 남겨 사람이 읽을 때와 AI가
해석할 때 모두 의미가 보존되게 한다.

카드 메타데이터는 카드 이름 뒤에 `진영`, `비용`, `역할`, `실행순서`, `태그`, `대상` 순으로 출력한다.
진영은 항상 출력한다. 아군 완성 카드의 비용과 역할도 항상 출력하며, 적군은
`- 비용: 없음`, `- 역할: 실행`을 출력한다. 실행순서는 모든 실행 카드에 출력한다.

### 9.2 여러 카드 묶음과 공용 선택

목록에서 체크한 카드가 모두 완성이면 하나의 파일로 내보낸다. 한 장만 선택하는 것도 허용한다.
완성·미완성 카드 모두 체크할 수 있고 `전체 체크`는 현재 검색 결과와 무관하게 모든 카드를 선택하거나
해제한다. 묶음 안의 카드 순서는 선택 순서가 아니라 현재 `cards[]` 목록 순서를 따른다.

선택에 미완성 카드가 하나라도 포함되면 완성 카드만 조용히 추려 내보내지 않고 전체 내보내기를
중단한다. 화면에는 `미완성 카드는 내보낼 수 없습니다. 먼저 완성 상태로 저장하거나 선택을
해제하세요.`를 표시한다.

```markdown
# Fate Weaver 카드 아이디어

- 생성일: 2026-07-27
- 카드 수: 2
- 대상 규칙: `docs/superpowers/specs/2026-07-27-position-targeting-card-text-design.md`

## 첫 번째 카드

...

## 두 번째 카드

...
```

목록 아래의 기본 파일명은 로컬에 보존한다. `Markdown 내보내기`를 누르면 기본 파일명이 채워진
파일명 대화상자를 열며, 사용자는 다운로드 전에 일회성으로 수정할 수 있다. 대화상자의 수정값은
기본 파일명으로 저장하지 않는다. 앞뒤 공백을 제거한 이름이 대소문자와 관계없이 `.md`로 끝나지
않으면 `.md`를 한 번 붙인다. 이름이 비어 있으면 내보내기를 막지 않고 날짜를 포함한
`fate-weaver-card-ideas-YYYY-MM-DD.md`를 사용한다. 읽기와 쓰기는 `.md` 파일만 지원한다.
대화상자는 `Enter`로 확인하고 `Escape`나 취소 버튼으로 닫을 수 있다.

선택 없음과 미완성 카드 포함 여부를 먼저 검사하고 내보낼 수 있을 때만 파일명 대화상자를 연다.
파일명은 카드 내보내기 가능 여부를 결정하는 검증 항목이 아니다.

완성 카드를 편집해 미완성으로 바뀌어도 공용 선택은 유지한다. 사용자는 그 카드를 다시 완성하거나
선택을 해제한 뒤 내보낼 수 있다.

### 9.3 Markdown 불러오기

`Markdown 불러오기`는 이 도구가 생성한 여러 카드 묶음 `.md` 파일만 받는다.

1. 파일 전체를 문자열로 읽는다.
2. 묶음 헤더, 선언된 카드 수, 각 `##` 카드 절, 메타데이터, 능력과 메모 구조를 임시 데이터로
   파싱한다.
3. 모든 카드를 현재 카드 모델로 정규화하고 핵심 정보 조건에 따라 완성 상태를 판정한다.
4. 하나라도 파싱, 구조 검증 또는 양 진영 동시 `자신` 규칙에 실패하면 기존 상태를 전혀 바꾸지 않고
   파일 전체를 거부한다.
5. 전체 검사가 성공하면 모든 카드를 새 카드로 한 번에 추가하고 한 번의 저장소 쓰기로 확정한다.

새 Markdown은 `진영`을 필수로 출력한다. 진영 메타데이터가 없는 구형 Markdown은 아군으로 해석한 뒤
새 핵심 정보 규칙으로 완성 상태를 판정한다. 구형 파일의 카드가 핵심 정보를 충족하지 못하면
`incomplete`로 불러오며, 형식 오류가 없는 한 파일 전체를 거부하지 않는다.

불러오기는 기존 카드를 ID나 이름으로 덮어쓰지 않는다. 이름이 겹치면 기존 목록과 같은 파일에서 먼저
추가된 카드까지 고려하여 `이름 (2)`, `이름 (3)`처럼 가장 작은 빈 번호를 붙인다. 불러오기 성공 후
추가된 첫 카드를 활성 카드로 보여준다.

## 10. 구성 요소

구현은 역할을 다음처럼 분리한다.

- 카드 모델 정규화와 비교
- 진영 불변식과 완성·미완성 상태 판정, 고유 이름 생성
- 검증과 경고 생성
- 위치 범위와 Markdown 생성
- Markdown 묶음 파싱과 원자적 불러오기
- `localStorage` 저장소와 스키마 검사
- 공용 목록 선택·검색·복제·단일 및 일괄 삭제
- 카드 목록 순서 변경과 파일명 정규화
- 편집 폼과 즉시 보존 실패 보호
- 현재 카드·전체 카드 명시적 저장과 키보드 단축키
- 선택 카드 Markdown 다운로드

순수 데이터 변환과 검증은 DOM 조작에서 분리해 브라우저를 열지 않고도 테스트할 수 있어야 한다.
