## 1. 목표 / 범위

현재 텍스트 중심의 기능적 전투 화면(`DeckPlaytestController` + 텍스트 상태줄/타임라인)을 **과슈 판타지 페이블 스타일의 시각적 전투 화면**으로 개편한다.

- 아트 스타일은 사용자가 확정: **과슈 판타지 페이블** (`prompt_v2/09_gouache_fantasy_fable`).
- 이번 설계가 정한 것: **화면 구도**, **턴 해석 연출 방식**, **카드 입력 방식**, **스프라이트 애니메이션 범위**, **아키텍처와 구현 단계**.
- 게임 로직(코어/시뮬레이션 순수 C#)은 변경하지 않는다. UI 레이어 교체가 전부다. (예외: §8 코어 이벤트 필드 추가 — 기존 테스트를 깨지 않는 추가만.)

## 2. 화면 구도 (확정: C안 "무대 + 레일" 수정판)

위에서 아래로 3단 구성:

```
┌─────────────────────────────────────── [전체 덱] ┐
│           유닛 무대 (플레이어 좌 / 적 우)          │
│   유닛마다 스프라이트 + 바로 아래 개별 HP 바        │
├───────────────────────────────────────────────┤
│  실행 영역 레일 (전폭, 좌우 드래그/스크롤)          │
│  미니 카드 = 프레임 + 일러스트 + 실행력 배지        │
├───────────────────────────────────────────────┤
│ (운명력)        곡선 손패           [턴 종료]     │
│ [뽑을 덱]                          [버린 덱]     │
└───────────────────────────────────────────────┘
```

- **유닛 무대**: 2D 사이드뷰, 플레이어 진영 좌 / 적 진영 우. 양측 모두 유닛이 1개 이상일 수 있으므로 HP 바는 상단 HUD가 아니라 **각 유닛 오브젝트 아래에 개별 부착**한다. 상태이상 아이콘도 유닛 단위로 HP 바 주변에 표시.
- **실행 영역 레일**: 무대 바로 아래 전폭 스트립. 카드가 많이 쌓일 수 있으므로 **좌우 드래그(스크롤) 가능**. 왼쪽이 먼저 실행되는 순서 정렬.
- **손패**: 하단, **약간의 호를 그리는 곡선 배열**. 집어 올리면(드래그 시작) 카드 확대.
- **덱 버튼 3종**: 뽑을 덱 = 좌하단, 버린 덱 = 우하단, 전체 덱 = 우상단. 각각 누르면 해당 더미의 카드 목록 팝업.
- **운명력**: 좌측(뽑을 덱 위), 화면에서 가장 시인성 높은 자원 표시.
- **턴 종료 버튼**: 우측 중단(버린 덱 위).
- **실행 취소 버튼**: 좌측 중단. 선택 모드(§6)에서만 표시된다.

## 3. 실행 영역 미니 카드

레일 위 카드는 전체 정보(특히 텍스트)를 담기에 작으므로 **단순화 표현 + 호버 상세**의 2계층으로 나눈다:

- **미니 카드 구성**: 외곽 프레임(실행/개입 카테고리를 프레임 디자인으로 구분) + 일러스트 + **상단 중앙 실행력 배지**. 텍스트 없음.
- **호버**: 카드 위에 포인터를 올리면 전체 카드 정보(기존 `CardView` 포맷)를 미리보기로 띄운다.
- **보류**: 레일 아래에 "실행 영역 카드 전체 보기(텍스트 포함)" 버튼 — 호버만으로 불편한지 플레이테스트로 확인한 후 추가 여부 결정. 이번 범위에서 제외.

## 4. 턴 해석 연출

현재의 텍스트 로그 일괄 출력을 **타일 단위 순차 재생**으로 교체한다. "미래가 순서대로 현실이 된다"를 화면 구조로 표현하는 것이 목적.

기본 루프 (레일 왼쪽부터 반복):

1. **점등** — 다음 실행될 타일에 하이라이트, 레일이 해당 타일로 자동 스크롤
2. **액션** — 타일 소유 유닛의 스프라이트가 동작(공격/방어 등), 공격이면 대상 방향으로 이동 연출
3. **피해 연출** — 데미지 숫자 팝업, 피격 유닛 hit 애니메이션 + 히트 플래시, HP 바 감소 트윈. VFX 수준은 StS급으로 절제(약한 화면 흔들림, 파티클 남용 금지 — 아트 원칙과 일치)
4. **소모** — 타일이 버린 덱 방향으로 날아가며 제거, 다음 타일 점등으로

- **스킵/빨리감기**: 해석 중 클릭(또는 버튼)으로 배속/즉시 완료. 필수 기능.
- 유닛 사망 시 death 애니메이션 후 무대에서 제거. 승패 확정 시 결과 연출 후 종료.
- 개입 카드 적용(해석 전 조작 단계)의 레일 변화도 트윈으로: 순서 변경/교환 시 타일들이 미끄러지며 자리를 바꾼다. 즉시 스냅 금지.

## 5. 스프라이트 애니메이션

- 방식: **프레임 스프라이트 애니메이션** (트윈 단독 아님 — 사용자 확정). 이동/넉백/숫자 팝업 등 보조 트윈은 병행.
- 상태 세트 (사용자 확정):
  - **플레이어 5종**: idle(루프) / attack / hit / block / death
  - **적 4종**: idle(루프) / attack / hit / death
- 제작 파이프라인: AI 생성 스프라이트 시트(4×4, 16프레임 — `art_style_prompts_2026-07-07/style_test_prompts/sprite*` 실험 연장선), 과슈 스타일 고정 프롬프트로 일관성 유지. Unity에서 시트 슬라이스 → 상태별 클립.

## 6. 카드 입력 규칙 (역할 분리 제스처)

> **드래그는 "카드를 낸다", 클릭은 "대상을 선택한다".** 두 제스처의 역할을 섞지 않는다 — 드롭은 어떤 경우에도 대상 지정을 겸하지 않는다.

| 카드 | 대상 수 | 조작 |
|---|---|---|
| 실행 카드 | 0 | 레일에 드롭 = 배치 끝. 위치는 실행력이 자동 결정 (드롭 지점 무관) |
| 개입 카드 | 1+ | 레일에 드롭 = 사용 시작 → **선택 모드** 진입, 요구 대상 수만큼 레일 카드를 클릭 |

- **선택 모드**: "지금은 대상을 골라야 한다"를 강조하기 위해, 선택 후보 카드(레일)를 제외한 화면의 모든 요소를 딤 처리한다. 좌측에 **실행 취소** 버튼이 나타난다.
- **커밋**: 요구 대상을 모두 클릭한 순간 즉시 적용된다(운명력 소비도 이때).
- **취소**: 선택 모드 중 실행 취소 버튼 클릭 → 카드가 손으로 복귀, 소비 없음.
- 드래그 중 유효 드롭 존(레일)에 하이라이트 표시. 운명력 부족·잠금 등으로 낼 수 없는 카드는 드래그 시작 시점부터 시각적으로 구분.
- 기존 클릭 2단계 입력은 드래그 시스템 완성 후 제거한다 (병행 유지 안 함). 단, **선택 모드 UX(딤 + 실행 취소 버튼)는 1단계의 임시 클릭 입력에도 동일하게 적용**한다 — 개입 카드를 클릭해 무장한 상태가 곧 선택 모드다.

## 7. 아키텍처

핵심 원칙: **로직 무변경.** `DeckCombatSession`(순수 C#, 헤드리스 테스트 보호)을 그대로 소비하는 새 UI 레이어를 만든다. 새 전투 씬을 추가하고 기존 `FateWeaverPlaytest` 씬은 디버그용으로 유지한다.

컴포넌트 (단일 책임 단위):

| 컴포넌트 | 책임 | 의존 |
|---|---|---|
| `BattleScreenController` | 씬 조립·세션 수명 관리 (현 `DeckPlaytestController` 대체) | 세션, 하위 뷰 전부 |
| `UnitView` | 유닛 1기의 스프라이트 + HP 바 + 상태 아이콘 | `SpriteSheetAnimator` |
| `SpriteSheetAnimator` + `UnitAnimationSet`(SO) | 시트 → 상태별 클립 재생 (idle 루프, 원샷 콜백) | 없음 |
| `ExecutionRailView` / `RailCardView` | 스크롤 레일, 미니 카드, 호버 프리뷰(기존 `CardView` 재사용), 하이라이트 | `CardPresentation` |
| `HandFanView` | 곡선 손패 배치, 드래그 시작점 | `CardView` |
| `CardDragController` | 제스처 상태 머신: Idle → Dragging → SelectTargets(n) → 커밋/취소. 드롭 = 카드 사용 시작, 대상은 클릭 선택. 선택 모드의 딤 레이어/실행 취소 버튼 제어. 세션 `PlayExecutionCard`/`PlayInterventionCard` 호출 | 세션 |
| `ResolutionPresenter` | `session.LastTimeline`을 시간축 연출로 재생, 스킵/배속 | `ResolutionScriptBuilder` |
| `ResolutionScriptBuilder` (**순수 C#**) | 타임라인 이벤트 목록 → 연출 스텝 목록 변환. 헤드리스 테스트 대상 (기존 `DescriptionComposer` 패턴) | 코어 이벤트 |
| `PileView` ×3 | 뽑을/버린/전체 덱 버튼 + 카드 목록 팝업 | `CardView` |
| VFX 소품 | `DamagePopup`, 히트 플래시, 약한 화면 흔들림 | 없음 |

**코어 이벤트 갭**: 현재 `CardResolved`는 카드ID/조건 티어/피해량만 담는다. 연출에 필요한 정보(카드 소유 진영, 대상 유닛, 방어 획득량, 상태이상 부여)가 부족하면 **코어 이벤트에 필드/이벤트 타입을 추가**한다. 기존 헤드리스 테스트를 깨지 않는 순수 추가만 허용하며, 계획 단계에서 필요 필드를 먼저 목록화한다.

## 9. 구현 단계 (각 단계 종료 시 플레이 가능)

1. **화면 골격** — 새 씬 + 구도 전체(무대/레일/곡선 손패/덱 버튼 3종/유닛별 HP 바) + 선택 모드 UX(딤 + 실행 취소 버튼). 정지 이미지, 기존 클릭 입력 임시 유지.
2. **드래그 입력** — `CardDragController`(드래그 = 카드 내기, 클릭 = 대상 선택), 완료 후 클릭 입력 제거.
3. **순차 해석 연출** — `ResolutionScriptBuilder`/`ResolutionPresenter`. 스프라이트 자리는 정지 이미지 트윈으로 임시.
4. **스프라이트** — 시트 제작 파이프라인 + `SpriteSheetAnimator` 통합.
5. **최종 아트 패스** — 배경/프레임 교체, VFX 폴리시.

각 단계는 독립 계획(`writing-plans`)으로 실행한다. 1단계부터 시작.

## 10. 검증

- **헤드리스 (`dotnet test`)**: `ResolutionScriptBuilder`의 타임라인→연출 스텝 매핑, 드래그 상태 머신의 순수 로직부(대상 수 판정, 커밋 조건).
- **Unity EditMode**: 아트/텍스트 룩업 가드 (기존 `FateWeaver.Tests.UnityEditMode` 패턴).
- **Unity Play 수동**: 화면 구도, 조작감, 연출 타이밍 — 단계별 체크리스트를 계획 문서에 포함.
