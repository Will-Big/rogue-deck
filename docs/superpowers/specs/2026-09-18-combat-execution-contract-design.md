### 2. 최종 실행 의미

- 실행 카드는 비용 지불과 동시에 번호에 따라 배치되며 회수 불가. 조작 카드는 직접 선택한 대상과
  사용 가능 조건을 검증한 뒤 적용한다. 조건 실패 시 사용·비용 소비가 없다.
- 카드가 자기 차례를 맞으면 실행된다. 조건 불충족이나 효과 미적용도 실행 사실을 지우지 않는다.
- 카드 성공 조건은 시작 시 한 번 평가한다. 성공 결과에 따른 기본/강화 값 또는 효과 생략을 고정한다.
- 효과들은 저작된 순서로 처리한다. 개별 효과 직후 사망 정리와 반응을 마치고 다음 효과로 간다.
- 각 효과 시작에 현재 위치 규칙으로 대상을 선택한다. 앞 효과 또는 반응으로 죽거나 이동한 결과를 반영한다.
- 광역 효과 하나는 시작 시 대상 목록을 확보해 전체에 적용하고 사망을 반영한 뒤 반응을 처리한다.
- 카드가 시작된 후에는 수행자가 죽어도 남은 효과를 수행한다. 죽은 개체는 일반 대상 선택에서 제외한다.
- 승패는 카드의 모든 효과 및 그 직접 반응이 끝난 뒤 판정한다. 패배(아군 전멸)가 승리보다 우선한다.
  마지막 적이 죽어도 뒤의 생존 아군 회복은 수행한다. 카드 도중 승패를 확정하거나 다음 효과를 생략하지 않는다.
- 승패 확정 후 다음 카드·턴 종료 상태·다음 턴은 실행하지 않는다. 종료 카드의 실행 결과와 전투 종료 이벤트는 출력한다.
- 내부 반응은 플레이어 입력을 요구하지 않는다.

폐기된 대화 중간안: 카드 전체 대상 고정, 효과마다 승패 판정, 수행자 사망 시 현재 카드 중단,
카드 종료까지 반응 보류, 임의 수행 묶음, 공격 반복만을 위한 별도 반응 경계.

### 3. 책임 경계와 제안 파일

아래 이름은 신규 제안이다. 기존 레지스트리·처리기를 재사용하며 거대한 중앙 switch를 추가하지 않는다.

| 단위 | 책임 | 모르는 것 | 제안 변경 지점 |
|---|---|---|---|
| 콘텐츠 변환 경계 | 검증된 카드 정의 생성 | 전투 중 개체·결과 | Authoring/CardSpec.cs, CardSpecMapper.cs, AuthoringValidator.cs |
| FutureZone | 현재 카드 자리 관리 | 피해·상태 능력 | Combat/FutureZone.cs |
| TurnResolver | 턴 단계 호출 순서 | 개별 조건·효과 계산 | Combat/TurnResolver.cs |
| CardExecutor | 카드 실행 진행 | 피해 공식·구체 상태 이름 | Combat/CardExecutor.cs 신설 |
| EffectExecutor | 효과 적용 경계 수행 | 카드 전체 분기·턴 진행 | Effects/EffectExecutor.cs 신설 |
| ReactionDispatcher | 사건에 반응하는 능력 실행 | 개별 효과 계산 | Status/ReactionDispatcher.cs 신설 |
| StatusLifetimePolicy | 상태 만료 판단 | 독·방어 등 개별 능력 | Status/StatusLifetimePolicy.cs 신설 |

보조 값 객체: CardExecutionContext(고정 조건 결과·현재 효과·효과 결과표),
EffectResult(적용 여부·소비량·피해 등 타입화 결과·사건), CombatSignal(발생 원인·주체·대상·순서),
ExecutionRecord(카드 실행 사실), ExpiryPolicy(시점·남은 횟수).
모든 객체를 각각 중앙 서비스로 만들지 않는다. 값 객체는 상태를 보관하고 처리기는 자신의 계약만 수행한다.
사망 정리는 공통 처리 경로에서 실행선 및 덱 제거를 수행한다. 카드 실행기는 실제 HP 계산을 하지 않는다.
효과 처리기는 카드 전체 취소나 다음 효과 호출을 하지 않는다.

### 4. 콘텐츠와 직렬화 계약

실행 카드 정의에는 아군 위치 규칙, 적군 위치 규칙, 선택적 카드 시작 조건,
순서 있는 효과 정의를 둔다. 효과는 적용 대상 축을 참조하며 같은 축의 위치 규칙을 중복 저작하지 않는다.
여기서 축은 파티/적 진영의 기존 의미와 일치시킨다. 적 카드의 Self 등은 행위자 기준 참조로 명시하고
변환 시 무조건 플레이어 Self로 해석하지 않는다. 다중 적 정책 변경은 수행하지 않는다.

조건의 판정 위치와 효과 수행 위치는 별개다. 대상 상태를 읽는 카드 시작 조건은 시작 당시 위치로
조건을 평가하지만, 이후 효과는 현재 위치에서 대상을 다시 선택한다. 조건 결과만 고정한다.
효과는 카드 조건의 성공/실패에 따른 수치와 생략 여부를 표현할 수 있다.
앞 효과 결과를 읽는 보상 요건은 카드 시작 조건 타입에 넣지 않는다.

JSON → 다형 CardSpec/EffectSpec → 구조·참조 검증 → CardDefinition 흐름을 유지한다.
현재 스펙을 직접 런타임 가변 상태로 사용하지 않는다. 효과별 kind 키와 명시적 등록을 유지한다.
이번 변경으로 스키마 버전을 도입하며 신규 원본은 version 2로 내보낸다. 구형 변환은 로딩 경계의
변환기로 한정하고 실행 처리기에 구형 대상 선택 분기를 남기지 않는다.

로딩 검증:
- 대상 축 누락, 같은 축의 상충 위치, 미등록 효과·조건·상태·시점은 오류.
- 효과 ID는 카드 안에서 유일해야 한다. 결과 참조는 앞에 있는 효과만 허용한다.
- 소비량 참조는 소비량을 생산하는 효과에만 허용한다. 자기 참조·앞으로의 참조·잘못된 결과 종류는 오류.
- 일반 카드 조건들이 서로 다른 기존 콘텐츠는 자동으로 하나의 조건으로 합치지 않고 변환 오류와 위치를 보고한다.
- 오류에는 파일·카드 ID·효과 ID 또는 인덱스·JSON 경로를 담는다. 조용한 생략이나 실행 취소로 대체하지 않는다.
- 기본값 생략과 필수 키를 구분한다. export → import → export 의미 보존을 검증한다.

편집 도구의 화면 개편은 목적이 아니지만 새 규격을 출력·왕복하도록 최소한의 스키마·설명·내보내기 변경은
같은 전환에 포함한다. 게임만 새 형식으로 바꿔 기존 도구의 출력을 깨뜨리지 않는다.

### 5. 소비와 보상

Exact: 요구량 전부가 있어야 차감하며 부족하면 차감 0·보상 없음.
UpTo: 보유량과 한도 중 작은 만큼 차감한다. 실제 소비량을 결과에 담는다.
보상 효과는 특정 앞 효과 ID의 실제 소비량/성공 여부를 읽는다. 카드 전체 누적값을 암묵적으로 읽지 않는다.
소비가 만든 직접 반응은 보상 효과 전에 처리한다. 반응으로 소비 대상이 바뀌어도 이미 기록한 소비 결과는 유지한다.
여러 대상을 소비하는 확장은 대상별 결과를 보존해야 하며 집계 방식을 암묵적으로 정하지 않는다.
이번 검증은 단일 대상 소비 카드에 한정한다.

### 6. 실행선·이력

배치 기본값은 번호 오름차순, 동률은 플레이어 우선, 같은 진영은 해당 번호에 도착한 순서다.
다른 번호로 이동하면 목적 번호에서 같은 진영의 기존 카드 뒤에 삽입한다.
정확한 자리 교환은 카드의 번호와 자리를 함께 교환하며 동률 진영 우선순위를 다시 적용하지 않는다.
조회·실행 시작에 재정렬하지 않는다. 아직 확정되지 않은 실행 중 순서 조작 능력은 추가하지 않는다.

제안하는 교환 후 삽입 세칙: 기존 카드들 상대 순서는 보존한다. 새 플레이어 카드는 그 번호의 마지막
플레이어 뒤(없으면 번호 구간 맨 앞), 새 적 카드는 번호 구간 맨 뒤에 넣는다. 이는 교환으로 뒤집힌
기존 적을 다시 정렬하지 않기 위한 구현 제안이며 HTML에서 명시한다.

사망한 주체의 미실행 카드만 제거한다. 이미 실행된 카드와 현재 실행 중인 카드는 이번 턴에 남는다.
파티원의 손패·뽑을 더미·버린 더미 소유 카드 제거는 사망 정리에서 즉시 수행한다.
실행 이력과 실행선은 다른 질의다. 카드 시작 조건은 이전 이력을 읽은 뒤 현재 실행 사실을 기록한다.
효과가 없거나 현재 카드 주체가 도중에 죽어도 실행 사실은 남는다.
‘직전에 실행된 카드’는 이력, ‘앞/뒤/인접 배치’는 현재 실행선을 참조한다.
설명 변경 대상만 이력 조건으로 옮기며 모든 배치 조건을 이력 조건으로 일괄 치환하지 않는다.

### 7. 사건·반응·피해

CombatSignal은 규칙 수행용 사실이며 사용자 표시용 ResolutionEvent와 구분한다.
공격받음, 체력 피해, 상태/방어 획득, 이동, 사망 등 사건 종류는 키·명시적 등록으로 확장한다.
반응 능력은 사건 종류·추가 조건·생존 요건·효과를 정의한다. 반격은 생존이 필요하고 사망 능력은
사망 사건에서 실행 가능하다. 모든 능력에 일괄 생존 검사하지 않는다.
방어로 전부 막아도 공격받음 사건은 발생한다. 체력 피해 사건은 실제 HP 감소시에만 발생한다.
관통은 방어 흡수를 우회하는 공통 피해 속성이다. 독만의 HP 차감 우회 경로로 표현하지 않는다.
독의 상태 피해를 공격받음과 자동으로 동치 취급하지 않는다. 피해 원인이 공격인지 상태인지 명시한다.

효과 시작 시 대상 목록 순서, 같은 보유자의 상태 부여 순서로 반응한다. 효과 내 여러 사건은
실제 발생 순서를 유지한다. 직접 반응 후보는 해당 효과의 경계에서 수집하고 다음 효과로 보류하지 않는다.
효과 대상 외 관찰자가 참여하는 경우는 안정적인 보유자 순서를 별도로 정의해야 한다. 이번 구현의
수용 범위는 사건 당사자의 반응이며 전역 관찰자를 몰래 배제한 채 확장 완료로 주장하지 않는다.

ReactionOrigin을 반응 효과에 전달한다. 반응에서 나온 사건은 기록·사망·카드 제거 등 필수 정리는
수행하지만 다른 반응 능력을 발동시키지 않는다. 따라서 반격 피해가 다른 반격, 방어 획득 반응,
사망 능력을 연쇄 발동시키지 않는다. 피해 보정과 방어 흡수는 반응이 아닌 기본 계산이므로 정상 적용한다.
신규 상태 재부여는 수치/수명 정책을 적용하되 기존 목록 위치를 유지한다.

### 8. 턴·수명·종료 경계

턴 준비(공통 만료 처리·비용 초기화) → 턴 시작 상태 → 적 배치·드로우 → 플레이어 행동
→ 실행선 처리 → 턴 종료 상태 → 턴 정리(카드 더미 이동).
턴 종료 상태는 보유자의 부여 순서로 수행한다. 개별 사망은 즉시 반영하며 같은 시점 처리가 끝나면 승패 판정한다.
턴 시작 상태 묶음도 같은 원칙을 사용하고 전투가 끝나면 적 배치·드로우로 넘어가지 않는다.
방어는 다음 턴 준비 만료 정책을 사용한다. 방어 전용 단계나 상태 키 분기는 추가하지 않는다.
일반 만료 정책은 기준 시점과 남은 방문 횟수, 영구/소모 종료를 표현한다. 시점 진입 당시의 기존 상태만
그 경계에서 만료시켜 도중에 새로 얻은 상태가 즉시 사라지지 않게 한다.

승패 판정은 카드 하나(직접 반응 포함) 또는 턴 시점 묶음의 끝에서만 수행한다. 패배 우선.
손패·드로우·셔플 규칙은 유지: 생존 파티 수별 드로우, 비용 이월 없음, 사용/미사용 카드 정리,
드로우 부족 시 버린 더미를 시드 RNG로 섞어 남은 장수 보충.

### 9. 대표 실행 예시

가상 카드: 적군 FrontOne, 효과 d1=피해 3, b1=자신에게 방어 3, d2=피해 3.
아군 P의 HP 10, 적 A의 HP 8이며 A는 공격받을 때 피해 2 반격. 다른 보정은 없다.
CardExecutor가 조건 결과를 고정한다. EffectExecutor(d1)는 A를 선택해 HP 5로 만들고 사건을 반환한다.
ReactionDispatcher는 A의 반격을 실행해 P의 HP를 8로 만든다. 반응에서 추가 반응은 발생하지 않는다.
EffectExecutor(b1)는 생존 P를 선택해 방어 3을 준다. d2는 현재 FrontOne A를 선택해 HP 2로 만든다.
A의 두 번째 반격은 방어 2를 소모해 P의 HP 8·방어 1을 남긴다. 카드 종료 결과는 Ongoing.
같은 카드의 d1이 마지막 적을 처치한다면 b1은 수행되고 d2는 대상 부재로 미적용된 뒤 Win이다.

### 11. 계획 검토에서 추가된 결정 (2026-09-18 사용자 결정)

[구현 계획](../plans/2026-09-18-combat-execution-contract.md)의 「검토 반영 결정」 D1~D8 중 게임 규칙에 해당하는 것이다.
위 절과 충돌하면 이 절이 우선한다.

- 독 피해는 원인=상태, 관통(방어 흡수 우회), 피해 배율 미적용이다. §7의 "관통은 공통 속성"을 따르며 결과는 현재
  동작(`Assets/Core/Status/PoisonBehavior.cs:32`)과 같다. (D1)
- 결과 참조는 성공 여부·최소 소비량(`requires`)에 더해 **소비량 비례 가산**(`scaleBy`: 앞 소비 효과의 실제
  소비량 × 계수)을 둔다. `condensed_burst`의 `damageBonusPerConsumed`가 이것으로 옮겨진다. §4의 참조 검증을 똑같이 받는다. (D2)
- 치명타 버티기(`SurviveCharges`·`DeathsDoor`)는 제거한다. 파티원은 치명 피해에 바로 사망하며 §2·§6의 사망 규칙이
  예외 없이 적용된다. 재도입은 별도 설계로 한다. (D8)
- 턴 시작·턴 종료의 상태 처리는 Primary 기원이다. 독 틱 사망에도 사망 능력(전염)이 발동한다. (D7)
