# 실행 카드 자동 위치 프리뷰 설계

## 1. 목적

대상 선택 중 화면 가운데 카드를 잠깐 표시하는 강조 연출을 제거한다. 대신 대상이 없는 실행 카드를 잡고
실행 영역에 마우스를 올렸을 때, 카드가 실제 최종 위치에 들어간 모습을 배치 전에 보여준다.

프리뷰는 카드의 실행 순서와 현재 상태 효과를 반영해야 하며, 실제 배치와 같은 위치를 가리켜야 한다.

## 2. 범위

### 포함

- 명시적 대상 클릭 뒤 화면 가운데 나타나는 카드 강조 연출 제거
- 대상 없는 실행 카드의 자동 삽입 위치 계산
- 실행 레일 내부의 반투명·푸른색 프리뷰 카드
- 실행 영역 진입·이탈, 성공·취소에 따른 프리뷰 생명주기
- 코어 위치 계산 헤드리스 테스트와 Unity EditMode 표현 테스트
- 전투 화면 수동 플레이 체크리스트 갱신

### 제외

- 마우스를 따라다니는 잡은 카드 제거
- 마우스 가로 위치로 삽입 지점을 선택하는 규칙
- 명시적 아군·적·실행 순서 카드 대상 선택 UX 변경
- 실제 카드 실행 순서, 상태 효과, 동률 정렬 규칙 변경
- 새 프리팹, 외부 에셋 또는 외부 패키지 추가

## 3. 상호작용 규칙

### 3.1 대상 선택

아군, 적 또는 실행 순서 카드를 대상으로 선택해도 화면 가운데 별도의 전체 카드가 나타나지 않는다.
선택한 손패 카드의 황금색 테두리, 대상 화살표, 후보/선택 대상 테두리는 기존대로 유지한다.

### 3.2 대상 없는 실행 카드 배치

1. 손패의 대상 없는 실행 카드를 클릭한다.
2. 손패 원본은 기존처럼 반투명해지고, 잡은 전체 카드는 마우스를 따라다닌다.
3. 실행 영역 밖에서는 레일 프리뷰 카드를 표시하지 않는다.
4. 실행 영역에 마우스가 들어오면 실제 최종 삽입 위치에 레일 크기의 프리뷰 카드를 표시한다.
5. 프리뷰 카드는 알파 0.5의 반투명 상태와 기존 `Secondary` 푸른색 테두리를 사용한다.
6. 프리뷰가 레일의 가로 레이아웃에 참여해, 뒤쪽 기존 카드가 실제 배치 후 모습처럼 밀린다.
7. 실행 영역에서 마우스가 벗어나면 프리뷰를 숨기고 기존 카드 간격을 복구한다.
8. 실행 영역을 클릭하면 기존 배치 요청을 수행한다.
9. 배치 성공, 선택 취소, 다른 카드 선택, 세션 초기화에서 프리뷰를 정리한다.

실행 카드를 잡은 동안 기존의 은은한 실행 영역 드롭 힌트는 유지한다. 기존 레일 카드의 전체 카드 호버
프리뷰는 숨겨, 배치 위치 프리뷰와 동시에 나타나지 않게 한다.

## 4. 자동 위치 계산

프리뷰 위치는 마우스 좌표가 아니라 실제 전투 규칙으로 계산한다.

1. 선택한 손패 카드의 기본 실행 순서를 읽는다.
2. 카드 소유자의 현재 상태 이상을 `StatusExecutionOrder.ExecutionOrderFor`에 적용한다.
3. 현재 `FutureZone`의 카드와 가상 후보 카드를 실제 `ResolutionOrder` 규칙으로 정렬한다.
4. 실행 순서 오름차순, 같은 실행 순서의 플레이어 우선, 같은 진영·같은 실행 순서의 안정 정렬을 적용한다.
5. 가상 후보 카드의 인덱스를 프리뷰 삽입 위치로 반환한다.

계산은 읽기 전용이다. 운명력, 손패, 버린 카드, 미래 영역, 인스턴스 ID, RNG 상태를 변경하지 않는다.
실제 `PlayExecutionCard`와 프리뷰가 다른 실행 순서를 계산하지 않도록 소유자 상태 조회와 유효 실행 순서
계산 로직을 한 곳에서 공유한다.

유효하지 않은 손패 인덱스, 실행 카드가 아닌 카드, 해결 완료된 턴 또는 운명력 부족 상태에서는 프리뷰
계산을 거부한다. 전투 화면은 이 경우 배치 모드에 진입하지 않고 기존 안내 메시지를 사용한다.

## 5. 구조

### 5.1 순수 코어

`DeckCombatSession`이 손패 인덱스를 받아 다음 두 값을 제공하는 읽기 전용 프리뷰 API를 소유한다.

- 상태 효과가 적용된 최종 실행 순서
- 현재 실행 레일에서의 최종 삽입 인덱스

`FutureZone`은 가상 `ExecutionCardInstance`를 실제 정렬 규칙에 포함했을 때의 삽입 인덱스를 계산한다.
후보는 컬렉션에 추가하지 않으며, 기존 카드의 순서나 값을 변경하지 않는다.

### 5.2 전투 화면

`BattleScreenController`는 대상 없는 실행 카드 선택 시 코어 프리뷰 API를 호출한다. 손패의
`CardPresentation`을 최종 실행 순서로 복제해 `CardSelectionController`에 카드 데이터와 삽입 인덱스를 넘긴다.

명시적 대상이 필요한 실행 카드와 개입 카드는 이 프리뷰 경로를 사용하지 않는다.

### 5.3 선택 컨트롤러

`CardSelectionController`는 기존 잡은 카드와 선택 상태를 계속 관리한다.

- 배치 시작: `ExecutionRailView`에 프리뷰 데이터와 삽입 인덱스를 등록한다.
- 배치 종료: 성공·취소 경로에서 레일 프리뷰를 해제한다.
- 대상 선택: 중앙 강조 카드 생성, 코루틴, 상수, 정리 로직을 모두 제거한다.

### 5.4 실행 레일

`ExecutionRailView`가 포인터 진입·이탈과 프리뷰 카드 표현을 소유한다.

- 기존 `_cardPrefab`으로 `RailCardView` 하나를 필요할 때 생성하고 재사용한다.
- 생성된 카드에 입력을 비활성화하고 `CanvasGroup.alpha = 0.5`를 적용한다.
- `CardView.SelectionKind.Secondary`로 푸른색 테두리를 적용한다.
- 포인터 진입 시 `_content`의 계산된 sibling index로 이동한 뒤 활성화한다.
- 포인터 이탈, 배치 종료, 카드 목록 재구성 전에 비활성화한다.
- 배치 프리뷰가 등록된 동안 기존 레일 카드 전체보기 호버를 열지 않는다.

새 프리팹이나 새 UI 계층은 만들지 않는다. 프리뷰 인스턴스는 런타임에 기존 직렬화 프리팹을 복제한다.

## 6. 데이터 흐름

```text
대상 없는 실행 카드 클릭
  -> DeckCombatSession이 최종 실행 순서와 삽입 인덱스 계산
  -> BattleScreenController가 최종 순서 CardPresentation 생성
  -> CardSelectionController가 잡은 카드와 레일 프리뷰 등록
  -> 실행 영역 PointerEnter
  -> ExecutionRailView가 프리뷰를 삽입 인덱스에 활성화
  -> 실행 영역 클릭
  -> 기존 PlayExecutionCard 요청
  -> 성공 시 프리뷰 정리 후 실제 레일 다시 렌더링
```

## 7. 오류 및 정리

- 프리뷰 계산 실패 시 배치 모드와 프리뷰를 시작하지 않는다.
- `_cardPrefab` 또는 `_content`가 누락되면 초기화/테스트에서 명확히 실패하게 하고 임의 대체 UI를 만들지 않는다.
- 포인터 이벤트가 중복되어도 프리뷰 인스턴스는 하나만 유지한다.
- 비활성 프리뷰는 가로 레이아웃 공간을 차지하지 않는다.
- 카드 목록이 갱신될 때 활성 프리뷰를 먼저 숨겨 파괴 대상 목록과 섞이지 않게 한다.
- 선택 취소와 성공은 같은 기존 `EndSelectionVisuals` 정리 경로를 사용한다.
- 프리뷰 표시 여부는 실제 카드 플레이 가능 여부나 전투 상태를 변경하지 않는다.

## 8. 검증

### 8.1 헤드리스 테스트

- 더 빠른 실행 카드는 기존 첫 카드 앞의 인덱스를 반환한다.
- 더 느린 실행 카드는 마지막 인덱스를 반환한다.
- 같은 실행 순서에서는 플레이어 카드가 적 카드보다 앞선다.
- 같은 진영·같은 실행 순서의 새 카드는 기존 동률 카드 뒤에 위치한다.
- 가속/감속 상태가 적용된 최종 실행 순서와 삽입 인덱스를 반환한다.
- 프리뷰 호출 전후 운명력, 손패, 미래 영역, 다음 인스턴스 ID와 RNG 결과가 변하지 않는다.
- 유효하지 않은 카드나 해결된 턴은 프리뷰를 거부한다.

### 8.2 Unity EditMode 테스트

- 배치 프리뷰 등록 직후에는 레일 프리뷰가 숨겨져 있다.
- 실행 영역 진입 시 지정한 sibling index에 프리뷰가 표시된다.
- 프리뷰는 알파 0.5, 푸른색 테두리, 입력 비활성 상태다.
- 프리뷰가 활성화되면 기존 카드가 레이아웃에서 한 칸 밀린다.
- 실행 영역 이탈, 취소, 성공, 카드 목록 갱신에서 프리뷰가 숨겨진다.
- 배치 프리뷰 중 기존 레일 카드 전체보기 호버가 표시되지 않는다.
- 대상 클릭 후 오버레이 중앙에 별도 강조 카드가 생성되지 않는다.
- 기존 잡은 전체 카드는 배치 중 마우스를 계속 따라간다.

### 8.3 수동 플레이 검증

- 대상 없는 실행 카드를 잡아도 실행 영역 밖에는 레일 프리뷰가 없다.
- 실행 영역에 들어가면 실제 배치될 위치에 반투명 파란 카드가 나타난다.
- 실행 영역을 가로질러 움직여도 프리뷰 위치는 마우스를 따르지 않고 자동 최종 위치에 고정된다.
- 영역 이탈 시 프리뷰가 사라지고 기존 카드 간격이 복구된다.
- 클릭 배치 후 실제 카드가 프리뷰와 같은 위치에 나타난다.
- 가속/감속 상태와 실행 순서 동률 상황에서도 프리뷰와 실제 위치가 일치한다.
- 대상 선택 카드에서는 화면 가운데 강조 카드가 나타나지 않는다.
- 취소·배치 과정에서 Console 오류가 없고 카드나 운명력이 미리 소비되지 않는다.

## 9. 고려한 대안

- 오버레이에 프리뷰를 겹치는 방식은 기존 카드를 밀지 않아 실제 배치 결과와 시각적으로 다르므로 제외했다.
- 파란 삽입선만 표시하는 방식은 위치는 명확하지만 카드가 들어간 모습을 보여달라는 요구를 충족하지 못해 제외했다.
- 마우스 위치로 삽입 지점을 선택하는 방식은 현재 자동 실행 순서 규칙을 변경하므로 범위에서 제외했다.
