CSV로 저작하고 Unity로 표시하는 다국어 카드게임

2026-10-13 · 승인 대기 제안 · 첫 언어: 한국어·영어

카드 규칙은 JSON으로 계속 저작하고, 번역 문구는 CSV로 관리한다. 효과 데이터에서 언어와 무관한 설명 요청을 만든 뒤 Unity Localization이 선택 언어의 문장을 표시한다. 세션 인계용 상세

무엇을 만드나

전투·보상·결과 화면의 카드명, 효과·조건·개입 설명, 상태명·툴팁, 유닛 이름, HUD·버튼·안내 문구를 한국어·영어로 전환한다. 언어 선택은 저장하며, 열린 카드·툴팁도 갱신한다. 테스트 전용 화면과 개발 로그의 영문 번역은 첫 범위에서 제외한다.

현행은 한국어 문자열을 코드와 JSON에 분산해 보관한다. 확인 근거: DescriptionComposer.cs:15,108, BuiltInEffectDescriptionHandlers.cs:14, CardPresentation.cs:88, BattleHudView.cs:60 (전체 경로는 상세의 현행 구조 절).

번역 조회는 렌더러에 모인다. 이는 문장 변환의 단일 책임이며, 전투·입력·CSV 저작을 이 객체에 모으지 않는다. BattleScreenController에는 배선만 둔다.

의존 방향

런타임은 Unity 테이블을 읽는다. CSV는 저작·검수 원본이며, 자체 런타임 CSV 로더는 만들지 않는다. 숫자 변경은 효과 데이터에서 요청에 반영된다.

확장 축

런타임에는 locale·폰트와 카드 수치가 바뀐다. 키·인수 계약, 대상 메타데이터와 레지스트리 확장 방식은 고정한다. 언어 추가는 번역 열·locale·폰트를 추가하는 작업이며 게임 효과 코드를 복제하지 않는다.

CSV는 Content / Descriptions / UI로 나누고 공식 Key·Id·언어·댓글 열을 쓴다. JSON의 기존 표시명은 로더 호환을 위해 유지하며, 한국어 CSV와 불일치하면 검사에서 실패시킨다.

대안과 기각 이유

이 선택으로 나중에 어려워지는 것

  • 문자열을 받던 테스트·호출자를 설명 요청 모델로 바꿔야 한다.
  • 번역 변경에도 CSV 가져오기와 Addressables 빌드가 필요하다.
  • 복합 조건·조사·목록 연결은 언어별 실제 문장 검수가 필요하다.
  • JSON 기본 이름과 한국어 CSV의 일치 검사가 필요하다.

실행 예시

venom_thrust의 피해 2와 독 1을 핸들러가 effect.damage(amount=2), effect.apply_status(status=poison, amount=1) 요청으로 만든다. 컴포저는 두 요청을 같은 적 대상 아래 묶는다.

한국어영어 초안
카드명맹독 찌르기Venom Thrust
최종 본문피해 2. 독 1.Deal 2 damage. Apply 1 Poison.

Unity 렌더러가 CSV에서 가져온 템플릿에 수치·번역된 상태명을 넣는다. 영어로 바꾸면 같은 의미 요청을 다시 렌더링한다. 전투 상태와 시드에는 영향을 주지 않는다.

검증과 승인 범위

헤드리스에서 의미 요청·수치·조건을 검사한다. Unity에서는 실제 양쪽 언어의 Smart String 결과, CSV 왕복·ID 안정성·폰트 참조·Addressables 빌드를 검증한다. 마지막으로 사용자가 Play에서 줄바꿈·글자 누락·넘침을 확인한다.

Packages/packages-lock.json에는 Localization·Addressables가 없다. 이 제안에는 Unity Localization과 필수 의존 패키지 추가가 포함된다. 새 외부 폰트가 필요하면 별도 승인을 받는다. 구현은 전용 워크트리에서 수행하고 master 머지는 별도 승인 대상이다.

공식 기능 근거: CSV Import/Export, Smart Strings.
