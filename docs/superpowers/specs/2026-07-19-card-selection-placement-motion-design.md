# 카드 선택 및 타임라인 배치 모션 설계

## 1. 목적

손패 카드 선택 상태를 기존의 황금색 강조와 팬 회전 자세에서 분리해, 읽기 쉬운 호버 자세와 푸른
테두리로 통일한다. 실행 카드의 배치를 확정할 때는 손패 카드가 즉시 사라지고 타임라인 카드가 나타나는
대신, 손패의 큰 카드가 DOTween으로 이동·회전·축소되어 레일 실루엣 자리에 안착하는 과정을 보여준다.

이 설계는 `2026-07-18-execution-card-placement-flow-design.md`의 두 단계 입력 흐름을 유지한다.
손패 실행 카드 클릭은 배치 대기 상태를 만들고, 펄스 중인 레일 실루엣 클릭이 실제 배치를 확정한다.

## 2. 범위

### 포함

- 클릭해 선택한 손패 카드의 팬 회전 제거
- 선택한 손패 카드를 기존 호버 위치·크기로 고정
- 선택한 손패 카드의 황금색 표시를 푸른 테두리로 교체
- 실행 카드 실루엣 클릭 후 큰 손패 카드가 레일 위치까지 이동·회전·축소되는 DOTween 연출
- 연출 중 원본 손패 카드와 배치 실루엣 숨김 및 중복 입력 차단
- 연출 완료 뒤 기존 전체 UI 갱신으로 실제 레일 카드 표시
- 성공·실패·취소·파괴 경로의 tween 및 임시 비행 카드 정리
- Unity EditMode 자동 테스트와 수동 플레이 검증

### 제외

- 손패 팬의 기본 배치·호버 수치 변경
- 실행 카드의 자동 삽입 위치, 비용, 정렬 또는 대상 규칙 변경
- 실루엣을 클릭하는 두 단계 배치 흐름 변경
- 조작 카드의 대상 선택 규칙과 화살표 흐름 변경
- 코어 및 시뮬레이션 계층 변경
- 새 외부 패키지 또는 새 전용 카드 프리팹 추가

## 3. 사용자 상호작용

### 3.1 손패 카드 선택

1. 포인터 호버 중인 손패 카드는 현재처럼 팬 회전을 풀고, 위로 올라오며 확대된다.
2. 카드를 클릭해 선택하면 포인터가 벗어나거나 호버 입력이 억제되어도 이 호버 자세를 유지한다.
3. 선택된 카드의 회전은 `Quaternion.identity`이며 팬의 원래 기울기로 돌아가지 않는다.
4. 선택 강조는 `CardView.SelectionKind.Secondary`의 푸른 테두리를 사용한다.
5. 선택된 카드에 황금색 `Primary` 테두리를 사용하지 않는다.
6. 실행 카드 배치 대기와 조작 카드 대상 선택 모두 같은 손패 선택 표현을 사용한다.
7. 취소, 배치 실패, 대상 선택 완료 또는 화면 갱신 시 카드는 원래 팬 자세와 스케일로 복원된다.

### 3.2 실행 카드 배치 대기

1. 손패 실행 카드를 클릭하면 기존처럼 자동 삽입 위치의 레일 실루엣이 고정되고 펄스한다.
2. 손패 원본은 호버 자세와 푸른 테두리를 유지한다.
3. 이 단계에서는 카드·운명력을 아직 변경하지 않고 빈 영역 클릭으로 취소할 수 있다.
4. 실루엣 이외의 레일 카드나 배경 클릭은 배치를 확정하지 않는다.

### 3.3 실루엣 클릭과 배치 모션

1. 실루엣 클릭 즉시 재진입 플래그를 세우고 레일 실루엣 버튼과 손패 입력을 비활성화한다.
2. 선택된 손패 원본과 레일 실루엣의 변환을 캡처한다.
3. 기존 `CardView` 프리팹으로 비행용 시각 복제본 하나를 오버레이 레이어에 준비한다.
4. 출발점이나 목표가 유효하지 않아 준비에 실패하면 세션을 변경하지 않고 선택 상태를 정리한다.
5. 준비에 성공하면 기존 `SelectionResult`를 만든 뒤 세션에 실제 배치를 한 번 요청한다.
6. 세션이 요청을 거부하면 비행 연출을 시작하지 않고 준비한 복제본과 선택 상태를 정리한다.
7. 세션이 승인하면 비행용 카드를 선택된 손패 원본과 같은 화면 위치·크기·회전으로 표시한다.
8. 원본 손패 카드와 레일 실루엣을 숨기되 레이아웃 공간은 유지해 목표 위치가 움직이지 않게 한다.
9. 비행용 카드는 목표 위치로 이동하는 동안 레일 카드 크기로 축소되고 잠시 기울어진다.
10. 도착 시 목표 레일 카드의 중심, 크기와 회전에 맞춰 `0`도 상태로 안착한다.
11. 연출이 끝나면 비행용 카드를 정리하고 선택 머신을 성공 상태로 종료한다.
12. 마지막으로 기존 `RefreshAll()`을 호출해 손패와 실제 레일을 현재 세션 상태로 다시 렌더링한다.

세션 변경은 성공 여부를 확정하기 위해 tween 시작 전에 수행하지만, UI 갱신은 tween 완료까지 미룬다.
따라서 규칙 상태는 즉시 확정되면서도 화면의 출발 카드와 목표 위치는 연출 동안 안정적으로 유지된다.

## 4. 구조와 책임

### 4.1 `HandCardHoverEffect`

- `Hold(true)`는 현재 호버 표현인 회전 `0`, 위쪽 이동, 확대 스케일과 최상위 sibling 상태를 유지한다.
- `Hold(false)`는 실제 포인터 호버가 남아 있지 않을 때 캡처한 팬 자세로 복원한다.
- 선택 시작 시 hold를 먼저 적용한 다음 호버 억제를 적용해, 억제가 카드를 팬 자세로 되돌리지 않게 한다.
- 기존 호버 콜백 규칙과 상수는 변경하지 않는다.

### 4.2 `HandFanView`

- 실행 카드 배치와 명시적 대상 선택 모두에서 선택 인덱스의 `HandCardHoverEffect`를 hold 상태로 둔다.
- 선택된 손패 카드에는 `Secondary`를 적용한다.
- 비행 시작에 필요한 원본 카드의 화면 변환과 크기를 제공한다.
- 기존 `_cardPrefab`으로 비행용 `CardView`를 만들고 현재 `CardPresentation`을 바인딩한다.
- 비행용 카드의 모든 raycast와 버튼 입력을 비활성화한다.
- 비행 중 원본 카드만 투명하게 만들며, 해당 카드의 RectTransform과 팬 레이아웃은 유지한다.
- 완료·중단 시 원본 투명도를 복원하고 비행용 카드를 파괴한다.

비행용 오브젝트는 런타임 `new GameObject`로 만들지 않고 이미 직렬화된 `CardView` 프리팹을 재사용한다.

### 4.3 `ExecutionRailView`

- 현재 배치 실루엣의 `RectTransform`을 비행 목표로 제공한다.
- 비행 시작 시 실루엣의 펄스 tween과 입력을 종료하고, 알파만 `0`으로 만들어 레이아웃 공간을 유지한다.
- 이동·축소·회전 DOTween `Sequence`를 소유한다.
- 완료·취소·카드 목록 갱신·오브젝트 파괴 시 자신이 소유한 sequence만 종료한다.
- 완료 후 실루엣 알파·스케일·입력 상태는 공통 정리 경로에서 초기값으로 복원한다.

### 4.4 `CardSelectionController`

- 손패 선택 표현, 세션 적용, 비행 연출과 최종 UI 갱신의 순서를 조정한다.
- `BeginPlacement`에서도 선택한 손패 카드에 hold와 푸른 테두리를 적용한다.
- `BeginTargetSelection`의 선택 손패 카드 역시 푸른 테두리를 사용한다.
- 실루엣 클릭 시 `_tryApply`를 한 번만 호출한다.
- 실패하면 기존 거부·취소 경로를 사용하고 비행 연출은 시작하지 않는다.
- 성공하면 입력을 잠그고 비행 연출을 시작하되 `_onApplied`는 완료 콜백까지 지연한다.
- 완료 콜백에서 선택 머신 성공 처리, 공통 시각 정리, `_onApplied` 호출을 순서대로 수행한다.
- 연출 진행 플래그로 중복 실루엣 클릭, 취소 입력과 다른 손패 선택이 연출을 재진입하지 못하게 한다.

### 4.5 `BattleScreenController`

- 기존 `_selection.Initialize(TryApplySelection, CurrentValidTargets, RefreshAll)` 계약은 유지한다.
- `TryApplySelection`은 규칙 적용 성공 여부만 반환하며 tween을 알지 않는다.
- `RefreshAll`은 연출 완료 후 선택 컨트롤러가 호출하는 기존 `_onApplied` 경로로 실행된다.

## 5. DOTween 연출

비행 연출은 하나의 `Sequence`로 관리한다.

- 이동: 원본 손패 카드 중심에서 현재 실루엣 중심까지 월드 좌표로 보간
- 축소: 원본 표시 크기에서 `RailCardView` 목표 표시 크기까지 동시 보간
- 회전: 전반부에 작은 Z축 기울기를 만들고 후반부에 목표 회전 `0`으로 복귀
- 이동·축소 easing: `Ease.InOutCubic`
- 회전 easing: 전반 `Ease.OutSine`, 후반 `Ease.InOutSine`
- update: 기존 펄스와 동일하게 `SetUpdate(true)` 사용
- link: 비행 카드 `GameObject`에 `LinkBehaviour.KillOnDestroy`로 연결

지속 시간, 최대 기울기와 기울기 전환 비율은 Unity 레이어의 `[SerializeField] private` 튜닝값으로 둔다.
코드에서 여러 위치에 같은 수치를 중복하거나 전역 DOTween 설정을 변경하지 않는다. 전역
`DOTween.KillAll()`은 사용하지 않고, 배치 연출이 소유한 tween 참조만 종료한다.

## 6. 데이터 흐름

```text
손패 카드 클릭
  -> 선택 카드 Hold(true)
  -> 푸른 Secondary 테두리
  -> 실행 카드면 ConfirmPlacement + 레일 실루엣 펄스

레일 실루엣 클릭
  -> 중복 입력 차단
  -> SelectionResult 생성
  -> 원본 카드/목표 실루엣 좌표 캡처
  -> CardView 프리팹 비행 복제본 준비
  -> TryApplySelection
     -> 실패: 준비한 복제본 + 공통 선택 정리, tween 없음
     -> 성공: 세션 상태 확정, UI 갱신 보류
  -> 원본과 실루엣을 투명화
  -> DOTween 이동 + 축소 + 기울기 + 회전 복귀
  -> 비행 복제본/tween 정리
  -> 선택 머신 성공 처리 + EndSelectionVisuals
  -> RefreshAll
```

조작 카드 대상 선택은 비행 경로로 들어가지 않는다. 손패의 hold와 푸른 선택 테두리만 공유한다.

## 7. 오류 및 생명주기

- 유효하지 않은 손패 인덱스나 사라진 배치 실루엣은 비행을 시작하지 않고 안전하게 선택을 종료한다.
- 세션 적용 실패 시 원본 카드와 실루엣을 숨기지 않는다.
- 첫 실루엣 클릭 직후 버튼을 비활성화해 `_tryApply`가 두 번 호출되지 않게 한다.
- 비행 중에는 다른 손패 카드 선택, 빈 영역 취소와 레일 목표 선택을 무시한다.
- 세션 적용 전 tween 준비가 실패하면 선택을 정리하고 세션 적용을 호출하지 않는다.
- 세션 적용 성공 후 tween이 중단되면 시각 연출을 생략하고 성공 정리와 `RefreshAll`을 정확히 한 번 실행해
  UI가 변경 전 세션 상태에 머물지 않게 한다.
- tween 정리 시 원본 카드 알파, 실루엣 알파·스케일·입력과 hold 상태를 공통 정리 경로에서 복원한다.
- 화면 재시작, 오브젝트 비활성화 또는 파괴 시 비행 sequence와 임시 카드가 남지 않는다.
- tween 완료 콜백과 강제 정리가 동시에 발생해도 `_onApplied`와 임시 카드 파괴는 한 번만 수행한다.
- 비행 카드의 Graphic과 Button은 입력을 받지 않는다.
- 실제 레일 카드의 정렬 위치는 세션이 확정한 결과와 기존 `RefreshAll`이 결정하며 tween 좌표가 규칙을
  변경하지 않는다.

## 8. 검증

### 8.1 Unity EditMode 테스트

- 실행 카드 선택 후 원본이 호버 위치·확대·회전 `0`을 유지한다.
- 조작 카드 대상 선택 후에도 원본이 같은 hold 자세를 유지한다.
- 선택한 손패 카드의 테두리는 푸른 `Secondary`이고 황금색 `Primary`가 아니다.
- 선택 취소와 적용 실패 후 원본이 캡처한 팬 위치·회전·스케일로 복원된다.
- 세션 적용 실패 시 비행용 카드와 placement sequence를 만들지 않는다.
- 실루엣 첫 클릭은 적용 콜백을 한 번 호출하고 즉시 실루엣 입력을 막는다.
- 성공 시 기존 `RefreshAll` 콜백은 sequence 완료 전 호출되지 않는다.
- 비행용 카드는 손패 원본의 시작 변환과 레일 실루엣의 목표 변환을 사용한다.
- sequence 완료 후 비행용 카드와 tween 참조가 정리되고 `RefreshAll` 콜백이 한 번 호출된다.
- 목록 재구성이나 오브젝트 파괴가 sequence를 종료하고 투명도·스케일을 복원한다.
- 기존 호버 실루엣, 선택 펄스, 레일 상세 호버와 조작 카드 단일·다중 대상 테스트가 계속 통과한다.

### 8.2 수동 플레이 검증

- 팬 양쪽 끝처럼 기본 회전이 큰 카드도 클릭하면 수평 호버 자세로 고정된다.
- 실행 카드와 조작 카드 모두 노란색 없이 푸른 테두리로 선택된다.
- 포인터가 선택 카드 밖으로 나가도 선택 카드는 들린 자세를 유지한다.
- 실행 카드 실루엣 클릭 시 큰 카드가 부드럽게 기울고 축소되며 정확한 레일 위치로 이동한다.
- 도착한 카드는 기울지 않고 실제 미니 카드로 자연스럽게 교체된다.
- 빠른 연속 클릭에도 운명력 차감과 카드 배치가 한 번만 일어난다.
- 취소와 적용 실패에서는 비행 카드나 투명 카드가 남지 않는다.
- 비행 중 화면 입력으로 다른 선택 상태에 진입하지 않는다.
- Console에 파괴된 tween 대상, 중복 완료 또는 누락 참조 오류가 없다.

### 8.3 코어 회귀

이 변경은 Unity 표현 계층에만 한정된다. 코어 배치 규칙을 수정하지 않으며, 기존 헤드리스
`dotnet test` 전체 스위트가 그대로 통과해야 한다.

## 9. 고려한 대안

- 실제 손패 카드 오브젝트를 오버레이로 재부모화하는 방식은 복제본이 없다는 장점이 있지만, 팬의 부모,
  sibling, 앵커, pivot과 실패 시 복원을 모두 관리해야 해 제외했다.
- `RailCardView`만 손 위치에서 이동시키는 방식은 단순하지만 큰 카드가 레일 크기로 축소되는 연속성을
  보여주지 못해 제외했다.
- 세션 적용을 tween 완료 뒤로 미루는 방식은 연출 도중 전투 상태가 달라질 수 있고 완료 시 실패하면 이미
  성공처럼 보인 연출을 되돌려야 하므로 제외했다.
- 적용 직후 `RefreshAll`을 실행하고 새 레일 카드만 애니메이션하는 방식은 손에서 카드가 날아가는 요청을
  충족하지 못해 제외했다.
