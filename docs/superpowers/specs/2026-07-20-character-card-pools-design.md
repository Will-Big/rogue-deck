# Fate Weaver — 플레이어 캐릭터 및 카드풀 설계 프레임워크

- 작성일: 2026-07-20
- 개정일: 2026-07-21
- 상태: 포트 기반 재설계 규칙 확정, 기존 7종 카드 아이디어 재검토 중
- 범위: 캐릭터 설계 규칙, 메커니즘 분류, 포트 계약, 기존 캐릭터 7종·카드 112장 아이디어 인벤토리

## 1. 목적

이 문서는 Fate Weaver의 파티 덱빌딩 구조에 맞는 플레이어 캐릭터 7종과 카드풀을 제안한다.
완성된 밸런스 표가 아니라, 캐릭터의 플레이 감각과 파티 간 시너지 경로를 폭넓게 검토하기 위한
디자인 원안이다. 비용·피해·방어·상태 수치는 상대적인 성공 폭을 보여주는 초안이며 이후 플레이테스트로
교체한다.

핵심 원칙은 다음과 같다.

1. 모든 캐릭터는 혼자 시작해도 전투가 성립하도록 공격·방어·실행·조작의 범용 기반을 가진다.
2. 캐릭터의 정체성은 정확히 두 개의 핵심 컨셉으로 설명한다. 범용 기반과 포트는 추가 컨셉으로 세지 않는다.
3. 캐릭터 하나가 시너지의 생성·증폭·소비를 전부 완성하지 않는다.
4. 다른 캐릭터와의 연결은 완성된 세 번째 컨셉이 아니라, 공용 사건이나 상태를 한 방향으로 주고받는 작은 포트로 만든다.
5. 포트 전용 카드도 1인 파티에서 쓸모가 있어야 하며, 특정 캐릭터나 특정 카드 이름을 요구하지 않는다.
6. 강한 연계는 가능하면 두 장 안에서 성립시킨다. 1~3인 파티의 공유 덱과 드로우 3~5장에서는 긴 연계가 안정적으로 잡히지 않는다.
7. 조작 카드는 직접 피해뿐 아니라 실행선·대형·대상·비용·수치·텍스트·상태·지속 규칙을 바꿀 수 있다.

## 2. 포트 기반 캐릭터 구조

이 문서에서 **포트**란 캐릭터가 공용 메커니즘과 연결되는 작고 방향성 있는 접점이다. 포트는 독립적인
플레이 엔진이나 세 번째 컨셉이 아니다. 캐릭터의 한두 장이 공용 사건을 만들거나, 이용하거나, 다른
메커니즘으로 바꾸는 정도의 연결이다.

| 설계 층 | 역할 | 캐릭터당 기준 | 정체성에 포함 |
|---|---|---:|---|
| 범용 전투 기반 | 혼자서도 공격하고 생존하며 카드를 실행·조작하게 한다 | 공격·방어·실행·조작을 모두 확보 | 아니요 |
| 핵심 컨셉 | 캐릭터만의 반복 의사결정과 플레이 감각을 만든다 | 정확히 2개 | 예 |
| 시너지 포트 | 다른 카드풀과 공용 사건·상태를 주고받는다 | 2~3개 | 아니요 |

### 2.1 이 구조를 선택한 이유

Fate Weaver의 파티는 1명으로 시작해 최대 3명까지 늘어나고, 생존한 파티원 수에 따라 한 턴에 3~5장을
뽑는다. 모든 소유 카드가 하나의 덱에 섞이고 운명력도 공유한다. 따라서 캐릭터마다 완성된 메커니즘을
3~4개씩 넣으면 파티원이 늘어날수록 원하는 카드가 함께 잡히기 어렵고, 카드 한 장이 경쟁하는 운명력도
늘어난다.

또한 캐릭터가 사망하면 그 소유자의 덱·손 카드가 제거되고 미래 영역 카드도 취소된다. 특정 파티원이
있어야만 작동하는 카드는 전투 중 갑자기 죽은 카드가 되기 쉽다. 보상도 캐릭터 소유 카드 중 3장 선택
구조이므로, 좁고 완결된 조합 부품이 많을수록 보상 선택의 실패 폭이 커진다.

두 핵심 컨셉은 적은 드로우에서도 캐릭터의 정체성을 반복해서 보여주고, 범용 전투 기반은 어떤 캐릭터로
시작해도 전투를 성립시킨다. 포트는 카드풀을 희석하지 않는 적은 수의 카드로 여러 캐릭터와 연결되므로,
파티 구성이 바뀌어도 시너지는 남고 단일 캐릭터가 조합 전체가 되는 것은 막는다.

### 2.2 포트의 방향

| 표기 | 종류 | 계약 | 금지되는 형태 |
|---|---|---|---|
| `◎` | 핵심 컨셉 | 카드풀 여러 장이 반복적으로 만들고 이용하는 플레이 축 | 카드 한두 장만 사용하는 장식적 컨셉 |
| `↑` | 출력 포트 | 다른 카드가 이용할 수 있는 공용 사건·상태를 만든다 | 같은 카드풀이 생성부터 보상까지 완결 |
| `↓` | 입력 포트 | 다른 카드가 만든 공용 사건·상태에서 추가 가치를 얻는다 | 외부 공급이 없으면 카드가 완전히 무효 |
| `⇄` | 변환 포트 | 메커니즘 하나를 다른 메커니즘 하나로 번역한다 | 양방향 무한 순환이나 자급 엔진 |

예를 들어 `↑ 대상 변경`은 적이나 카드의 대상이 바뀌었다는 공용 사건을 자주 만든다는 뜻이고,
`↓ 대상 변경`은 누가 변경했는지와 관계없이 그 사건에서 보상을 얻는다는 뜻이다. 둘은 같은 컨셉을
공유하지 않아도 연결된다.

### 2.3 메커니즘 묶음

세부 효과를 모두 별도 컨셉으로 세지 않고, 유사한 의사결정을 만드는 것끼리 다음처럼 묶는다.

| 메커니즘 묶음 | 포함되는 조작과 사건 | 대표적인 포트 신호 |
|---|---|---|
| 전장 제어 | 아군·적 대형 이동, 위치 교환, 대상 지정·변경, 원래 대상 대신 다른 아군이 피해를 받는 피해 가로채기 | 이동함, 대상이 바뀜, 대신 맞음 |
| 실행선 제어 | 실행순서 가속·지연·교환·고정·취소, 실행 위치 조건 | 순서가 바뀜, 인접 실행, 첫·마지막 실행 |
| 카드 순환 | 드로우, 버림, 회수, 생성, 사용한 전투에서만 다시 돌아오지 않는 전투 한정 소멸 | 카드를 뽑음, 버림, 소멸함 |
| 카드 개조 | 비용·수치·대상·조건·효과·텍스트의 임시 또는 전투 중 변경 | 비용 감소, 텍스트 추가, 수치 변경 |
| 전투 자원·상태 | 운명력, HP, 방어, 축적형 상태, 상태 이전·소비 | 방어 획득·소진, 상태 부여·소비 |
| 지속 규칙·설치물 | 전투 동안 유지되는 규칙, 슬롯 제한 효과, 충전물 | 지속 규칙 설치·교체·발동 |
| 파티·소유권 | 카드 소유자, 다른 캐릭터 실행, 사망에 따른 카드 제거 | 다른 소유자 실행, 소유자 사망 |
| 정보·무작위 | 미래 실행선 공개, 예고, 결정론적 무작위 선택·재선택 | 공개함, 예측 적중, 무작위 결과 변경 |

런 중 보상 확률, 카드 제거, 강화 경로와 같은 덱 성장 규칙은 전투 메커니즘과 별도 층으로 관리한다.

### 2.4 캐릭터 계약서

캐릭터를 카드보다 먼저 다음 순서로 정의한다.

| 항목 | 작성 내용 | 통과 기준 |
|---|---|---|
| 정체성 문장 | 전투에서 무엇을 판단하고 어떤 위험을 감수하는가 | 두 핵심 컨셉이 한 문장에 드러남 |
| `◎` 핵심 컨셉 A | 반복해서 만드는 의사결정과 카드 사용 유형 | 단독으로도 공격·방어 선택에 관여함 |
| `◎` 핵심 컨셉 B | A와 독립적이거나 느슨하게 연결되는 두 번째 축 | A 없이도 카드 몇 장이 의미 있음 |
| 범용 기반 | 기본 공격·방어와 최소한의 능동 조작 | 1인 시작 덱이 막히지 않음 |
| 포트 2~3개 | `↑`, `↓`, `⇄` 중 방향과 공용 신호 | 포트마다 다른 캐릭터 후보가 2명 이상 |
| 혼자 쓸 때의 바닥값 | 외부 시너지가 없어도 카드가 하는 일 | 포트 카드가 완전한 무효가 아님 |
| 파티에서의 상한값 | 다른 카드풀과 만났을 때 추가되는 선택 | 특정 카드 이름 없이 두 장 안에 설명 가능 |
| 내부 완결 금지 | 캐릭터가 의도적으로 갖지 않는 생성·증폭·소비 | 한 카드풀이 조합 전체가 되지 않음 |

전열대장을 재설계할 때도 먼저 이 계약서를 확정한다. 예컨대 `전투 동안 하나만 유지되며 특정 카드군의
규칙을 바꾸는 지속 효과인 방진`을 핵심 컨셉으로 선택할 수 있지만, 이는 아직 확정된 계약이 아니다.
방진의 공격 수단, 교체 이유, 외부 포트까지 계약서에서 설명된 뒤 카드 목록을 만든다.

### 2.5 카드풀과 시작 카드

카드풀은 18~24장을 권장하되 컨셉을 표현하는 데 필요하면 범위를 조정한다. 아래 수는 카드의 기능이
겹칠 수 있는 검수 기준이며, 합계가 카드풀 크기와 같을 필요는 없다.

| 기능 | 권장 수 | 목적 |
|---|---:|---|
| 공격 기능 | 5장 이상 | 어떤 캐릭터로 시작해도 적을 쓰러뜨릴 수 있음 |
| 방어·생존 기능 | 4장 이상 | 특정 파티원 없이도 전투를 버틸 수 있음 |
| 조작 카드 | 4장 이상 | 컨셉에 맞게 실행 전후의 규칙을 능동적으로 바꿈 |
| 핵심 컨셉 A | 5~7장 | 반복 가능한 첫 번째 플레이 축 |
| 핵심 컨셉 B | 5~7장 | 반복 가능한 두 번째 플레이 축 |
| 포트 전용 카드 | 전체의 25% 이하 | 연결성을 만들되 정체성을 희석하지 않음 |
| 두 핵심 컨셉의 내부 연결 카드 | 0~2장 | 단일 캐릭터가 완성 조합이 되는 것을 방지 |

- `★`는 시작 후보를 뜻한다.
- 시작 덱은 기본 공격 1장, 기본 방어 1장, `★ 컨셉 실행` 중 무작위 1장,
  `★ 컨셉 조작` 중 무작위 1장으로 구성한다.
- 전투 한정 소멸 카드는 사용한 전투에서만 덱·손·버림 영역으로 돌아오지 않으며, 전투가 끝나면 복구된다.
- 지속 카드, 전투 한정 소멸 카드, 실행 카드, 조작 카드는 한 카드풀 안에서 함께 사용할 수 있다.

### 2.6 키워드 서술 규칙

키워드가 문서의 한 절이나 대화에서 처음 등장할 때는 이름보다 작동 방식을 먼저 쓴다.

- 권장: `전투 동안 하나만 유지되며 특정 카드군의 규칙을 바꾸는 지속 효과인 방진`
- 금지: 별도 정의 없이 `방진을 얻는다`
- 첫 설명에는 가능하면 유지 기간, 보유 주체, 발동 시점, 중첩·교체 규칙, 실제 효과를 포함한다.
- 한 번 정의한 뒤에는 같은 절이나 같은 대화 안에서 키워드 이름만 사용해도 된다.

### 2.7 카드 표기

| 표기 | 의미 |
|---|---|
| 현행 | 현재 효과·조건·조작 문법으로 표현 가능 |
| 조건 | 새 `Condition`이 필요함 |
| 효과 | 새 `IEffectHandler` 또는 효과 payload가 필요함 |
| 상태 | 새 상태 행동 또는 상태 훅이 필요함 |
| 조작 | 새 `IInterventionActionHandler` 또는 조작 payload가 필요함 |

조작 카드는 손에서 운명력을 지불해 즉시 해결되고 실행순서를 갖지 않는다. 별도 언급이 없는 실행 카드의 적 대상은
**해결 시점의 적 전열**이며, 실행 카드를 배치할 때 직접 대상을 고르지 않는다. 아군을 지정하는 실행
효과는 카드 문구에 적힌 규칙(예: HP가 가장 낮은 아군)으로 자동 선택한다. 조작 카드만 플레이 과정에서
엔티티·손패·미래 영역의 대상을 직접 고를 수 있다.

### 2.8 카드 타입과 프레임 명세

이 절은 카드풀 아이디어와 별개로 유지해야 하는 후속 UI·저작 명세다. 이번 카드풀 대화에서는 프레임의
시각적 완성도보다 아래 정보 구조를 우선 확정하고, 구체적인 색상·도형·아트 배치는 후속 세션에서 다룬다.

카드 표시는 서로 독립된 두 축을 가진다.

| 축 | 값 | 의미 |
|---|---|---|
| 카드 역할 | `실행`, `조작` | 실행선에 올라가는 카드인지, 손에서 즉시 해결되는 조작인지 |
| 카드 수명·출처 | `일반`, `흡수`, `토큰` | 사용 후 더미 처리와 카드풀·보상 소속 여부 |

#### 카드 역할

- `실행`: 비용과 실행순서를 가지며 미래 실행선에 배치된다. 프레임의 가장 눈에 띄는 영역에 `실행` 글자와
  고유 아이콘을 표시하고, 실행순서를 고정 영역에 표시한다.
- `조작`: 손에서 운명력을 지불해 즉시 해결되며 실행순서를 갖지 않는다. 프레임의 같은 영역에 `조작` 글자와
  다른 고유 아이콘을 표시하고, 실행순서 영역은 비워 두거나 조작 전용 표시를 사용한다.
- 색상만으로 역할을 구분하지 않는다. 글자·아이콘·레이아웃을 함께 사용해 색각 이상과 작은 화면에서도
  구분할 수 있어야 한다.

#### 카드 수명·출처

- `일반`: 사용 후 버린 카드 더미로 이동하는 기본값이다. 기본값이라도 필요하면 `일반` 배지를 표시한다.
- `흡수`: 전투에서 한 번 사용한 뒤 버린 카드 더미나 소멸 더미에 들어가지 않고 해당 전투에서 제거된다.
  프레임의 독립된 배지와 한 번 사용 아이콘으로 표시한다.
- `토큰`: 카드풀에 원래 포함되지 않고 전투 중 효과로 생성되는 카드다. 보상 대상이 아니며 전투 종료 시
  정리된다. 카드가 런타임에 토큰으로 생성되면 원본 카드의 역할·효과와 별개로 `토큰` 배지를 표시한다.
  따라서 토큰 여부를 카드 설명에 하드코딩하지 않는다.

`소멸.`은 프레임 수명 축의 별도 값이 아니라, 카드 사용 횟수와 사용 후 이동을 바꾸는 카드 효과 키워드다.
카드 텍스트에 직접 표시한다.

```text
소멸.       이번 사용 직후 소멸 더미로 이동한다.
소멸 3.     이 카드의 세 번째 사용 후 소멸 더미로 이동한다.
```

`소멸 3.`은 첫 번째·두 번째 사용 후 버린 카드 더미에 남고 세 번째 사용 후 소멸 더미로 이동한다는
뜻으로 고정한다. 전투 중 효과가 일반 카드에 `소멸.`을 부여할 수 있으므로, 카드 프레임의 기본 타입과
별개로 해결 시점의 텍스트를 우선한다.

지속, 대기, 회수, 부착은 별도 카드 타입으로 만들지 않는다. 카드 효과가 해결 후 필요한 상태·대상·이벤트를
직접 설명한다. 예를 들어 “다른 아군이 피해를 받을 때, 피해를 무효화하고 적에게 그 피해를 입힙니다.”는
카드 타입과 별개인 효과 문장이다. `흡수` 카드라면 그 효과 해결 후 카드가 전투에서 제거되고, `일반` 카드라면
효과 해결 후 버린 카드 더미로 간다.

프레임 조합은 다음 네 가지를 모두 같은 규칙으로 표현할 수 있어야 한다.

```text
실행 + 일반
실행 + 흡수
조작 + 일반
조작 + 흡수
```

토큰은 위 조합에 런타임 배지로 추가될 수 있다. 예를 들어 `조작 + 흡수` 카드가 전투 중 토큰으로 생성되면
`조작`, `흡수`, `토큰`을 동시에 표시한다.

이 절의 프레임 배치와 시각 언어는 카드풀 메커니즘 설계가 끝난 뒤 후속 세션에서 확정한다.

## 3. 공용 키워드 초안

이 절은 기존 카드 아이디어에서 사용한 키워드의 작동 계약이다. 제목에서 키워드를 짧게 표시하더라도
바로 아래 첫 문장이 유지 기간·발동 조건·효과를 설명하며, 이후에만 축약해서 사용한다.

### 방어

이번 턴에 받는 피해를 수치만큼 막는다. 카드 설계에서는 여러 방어 부여가 합산되는 것을 전제로 했지만,
현재 `StatusBag.Add`의 동일 키 재적용은 교체이므로 실제 구현 전에 합산·교체 규칙을 확정해야 한다.

### 표식 X

표식을 부여한 캐릭터가 아닌 다른 캐릭터의 **표식 보상 카드**가 대상에게 적중할 때 표식 1을 소비하고
그 카드의 추가 효과를 활성화한다. 일반 피해 카드에는 자동 보너스가 없다. 표식에는 부여자 ID가 기록되어야
한다.

### 협공

직전에 정상 실행된 플레이어 카드가 현재 카드와 다른 캐릭터 소유이며, 두 카드가 같은 적을 대상으로 했다면
성공하는 조건이다. 취소된 카드는 건너뛴다.

### 조건 보호

카드 인스턴스에 부여되는 1회성 상태다. 적의 `조건 보상 무효`를 한 번 막고 함께 소비된다. 조건 자체를
자동 성공시키지는 않으므로 실행선 조작은 여전히 필요하다.

### 시차

별도 자원이 아니라 실행순서 변경, 가속, 둔화, N번째 이내·이후, 첫·마지막 실행 조건을 묶는 설계 용어다.
낮은 실행순서가 먼저 발동한다.

### 독 X

턴 종료 시 X만큼 피해를 주고 독이 1 증가한다. 독 피해 자체는 표식을 소비하거나 카드 조건을 만족시키지
않는다. 장기전에서 무한히 증가할 수 있으므로 실제 밸런스 단계에서 최대치·정화·전투 길이를 함께 검토한다.

### 생사선

캐릭터의 현재 HP가 튜닝된 기준 이하이거나, 이번 전투에 죽음의 문턱 충전을 소비했다면 생사선 상태로
간주한다. HP 기준은 상수로 박지 않고 캐릭터·전투 튜닝 데이터로 둔다.

### 연명

이번 턴의 다음 치명 피해를 받으면 HP 1로 버티고 사라진다. 전투 기본 죽음의 문턱 충전보다 먼저
소비한다. 중첩되지 않고 지속시간만 갱신한다.

### 유언

카드 인스턴스에 부여되는 상태다. 소유자가 카드 실행 전에 사망해도 해당 카드는 한 번 정상 실행된 뒤
유언을 소비한다. 소유자를 대상으로 하는 `Self` 효과는 사망 상태에서 유효하지 않으므로 해당 효과만
건너뛰고, 적 대상 효과는 실행한다.

## 4. 기존 캐릭터·카드 아이디어 인벤토리

아래 7종과 카드 112장은 포트 방식이 확정되기 전에 작성한 아이디어 인벤토리다. 현재의 캐릭터 계약이나
최종 카드풀로 간주하지 않는다. 특히 인접 캐릭터끼리 컨셉 하나를 직접 공유하는 고리 구조, 캐릭터당 16장
고정, 실행 12장·조작 4장 고정은 폐기된 전제다.

재설계할 때는 캐릭터별로 2.4의 계약서를 먼저 작성한 뒤, 아래 카드에서 핵심 컨셉에 맞는 아이디어만
승계한다. 승계한 카드도 공격·방어 기반, 포트의 방향, 1인 플레이 바닥값, 사용 유형을 다시 검수한다.

## 5. 기존 파티 시너지 예시와 포트 재작성 규칙

아래는 정답 파티가 아니라 기존 카드 상호작용을 확인하기 위한 예시다. 새 설계에서는 캐릭터 이름을
직접 잇는 조합표로 확정하지 않고, 각 상호작용을 다음 형식으로 다시 쓴다.

1. 출력 캐릭터가 만든 공용 사건·상태를 `↑`로 적는다.
2. 입력 캐릭터가 이용한 같은 사건·상태를 `↓`로 적는다.
3. 혼자 사용했을 때 각 카드가 남기는 기본 효과를 함께 적는다.
4. 특정 카드 이름을 빼도 상호작용을 설명할 수 있어야 한다.
5. 같은 포트에 연결될 수 있는 세 번째 캐릭터 후보가 있는지 확인한다.

예: `↑ 적 이동`과 `↓ 적 이동`처럼 사건을 중심으로 연결한다. 단순히 “전열대장 + 황야추적자”를 하나의
고정 조합으로 만들지 않는다.

### 전열대장 + 황야추적자

`긴급 교대`나 `어깨 교대`로 추적자를 후열에 보내 `후열 사격`을 활성화한다. 추적자는
`몰아붙이는 사격`으로 위험한 적을 뒤로 보내고, 전열대장은 그 적의 카드들을 `전열 압박`으로 늦춘다.

### 황야추적자 + 검무가

추적자가 `신호 화살`로 표식을 만들고 `약점 포착`으로 서로 다른 소유자의 공격 대상을 통일한다.
검무가는 `표적 베기`, `교차 참격`으로 표식과 협공을 각각 소비한다.

### 검무가 + 운명점술사

검무가의 강한 연계 카드는 다른 캐릭터 카드와 인접해야 한다. 점술사의 `운명의 봉합`과 검무가의
`합 맞추기`는 서로 다른 범위의 실행선 문제를 해결하지만 어느 한 장도 전체 실행선을 완성하지 않는다.

### 운명점술사 + 역병의사

점술사는 빠른 `느린 처방`을 더 앞당겨 적의 다음 턴을 늦추거나, `숙성 완료`를 뒤로 보내 늦은 조건을
만든다. 역병의사의 `투약 연기`는 점술사의 상태 카드에도 적용되어 시차 선택지를 공유한다.

### 역병의사 + 장송인

역병의사는 여러 적에게 독을 만들고 증가시키지만 자유로운 이전 능력은 부족하다. 장송인은 독을
취약·방어·연명으로 바꾸거나 위험한 적 하나에 모아 파티의 다음 공격 목표를 만든다.

### 장송인 + 혈갑기사

혈갑기사가 자해와 낮은 HP 조건을 사용하고, 장송인이 `연명`과 `유언`으로 실패 비용을 제한한다.
혈갑기사 혼자서는 죽음 위험을 안정적으로 관리하지 못하고 장송인 혼자서는 생사선 조건을 능동적으로
만들기 어렵다.

### 혈갑기사 + 전열대장

전열대장은 방어를 공급하고 혈갑기사는 `방패 분쇄`, `균열 난 갑주`로 방어의 소진을 공격 가치로
바꾼다. 방어를 전부 소비하면 이후 적 공격에 노출되므로 매 턴 자동으로 선택할 수 있는 조합은 아니다.

### 비인접 조합

- 전열대장 + 운명점술사: `엄호 지점`과 순서 조작으로 원하는 시점에 방어를 발생시킨다.
- 황야추적자 + 역병의사: 독이 쌓인 적을 전열로 끌어내고 그 적의 카드를 늦춘다.
- 검무가 + 혈갑기사: 혈갑기사의 빠른 위험 카드가 검무가의 다른 소유자 연계를 연다.
- 운명점술사 + 장송인: 유언 카드의 실행을 늦게 보존하거나, 위험해지기 전에 앞으로 옮긴다.

## 6. 기존 아이디어가 요구하는 규칙 목록

이 절은 구현 계획이 아니라, 카드 재설계 시 비용을 판단하기 위한 목록이다.

### 6.1 조건

- 소유자의 현재 대형 위치: 전열, 후열, N번째
- 이번 턴 앞서 아군·적 대형이 변경됐는지
- 대상이 특정 상태를 가졌는지와 상태 부여자
- 직전 정상 실행 카드의 소유자가 다른지
- 협공: 다른 소유자 + 같은 대상
- N번째 이후 실행, 이후 적 카드 존재 여부
- 소유자 또는 임의 아군이 생사선인지
- 이번 턴 죽음의 문턱이 소비됐는지
- 해결 시 방어 잔량 또는 앞서 방어가 감소했는지

### 6.2 실행 효과

- 아군·적을 전열/후열/상대 위치로 이동·교환
- 자신 이외 아군, HP 최저 아군, 모든 다른 아군 대상으로 효과 적용
- 표식의 부여자 기록·소비·카드별 보상 활성화
- 다음 `다른 소유자` 카드에 피해 보너스나 상태 부여
- 기존 상태 수치 증가·감소·이전·소비
- 독의 턴 종료 피해와 성장
- 일시적 연명 부여와 죽음의 문턱 우선순위 처리
- 방어 소비량·잔량을 피해나 이전량으로 변환
- 제한된 자해와 자해로 인한 죽음의 문턱 처리 규칙

### 6.3 조작 대상과 payload

현재의 단일 실행 카드 대상 외에 다음 대상 모델이 필요하다.

- 손에 있는 카드 1장 또는 여러 장
- 미래 영역 카드 여러 장과 선택 순서
- 파티원과 적 엔티티
- 동일 소유자의 모든 미래 카드
- 상태가 있는 모든 적이 소유한 카드
- 선택 대상 없음 + 전투 RNG 무작위 대상
- 카드의 임시 비용·실행순서·효과 수치·대상 변경

무작위 조작은 반드시 `CombatState.Rng`를 사용하고, UI는 조작마다 요구되는 대상 종류와 최소·최대 개수를
조작 데이터에서 읽어야 한다.

### 6.4 상태와 해석 훅

- 엔티티 턴 종료 훅: 독
- 카드 실행 직전 훅: 엄호, 위험한 앞당김
- 카드 조건 보상 보호·무효화
- 소유자 사망 취소 예외: 유언
- 치명 피해 직전 훅: 연명
- 방어 감소 관찰: 균열 갑주
- 상태의 출처 캐릭터 ID: 표식

### 6.5 이벤트 타임라인

표현 레이어가 코어 상태를 직접 뒤지지 않도록 다음 결과는 이벤트로 노출해야 한다.

- 대형 이동·교환
- 표식·독의 부여, 소비, 이전, 턴 종료 발동
- 방어 획득·소비·이전
- 카드의 임시 변형과 대상 변경
- 연명 발동과 유언 실행
- 다중 카드 조작 전후의 실행선 변화

## 7. 포트 기반 재설계 체크리스트

각 캐릭터와 카드를 다시 다듬을 때 다음을 확인한다.

1. 캐릭터의 정체성을 정확히 두 개의 `◎` 핵심 컨셉으로 설명할 수 있는가?
2. 공격·방어·실행·조작의 범용 기반이 두 핵심 컨셉과 별개로 갖춰졌는가?
3. 기본 공격·방어·시작 후보만으로 두 핵심 컨셉 중 적어도 하나를 경험할 수 있는가?
4. 시작 조작 카드가 시작 실행 카드의 선택지를 넓히되 매번 자동 성공시키지는 않는가?
5. 포트가 2~3개이며 각각 `↑`, `↓`, `⇄` 중 한 방향으로 정의됐는가?
6. 각 포트가 특정 카드 이름 대신 공용 사건·상태를 사용하는가?
7. 각 포트에 연결 가능한 다른 캐릭터가 2명 이상인가?
8. 포트 카드가 1인 파티에서도 완전히 무효가 되지 않는가?
9. 같은 카드풀 안에서 포트의 생성·증폭·소비가 모두 완결되지 않는가?
10. 파티 시너지를 가능하면 카드 두 장 안에서 설명할 수 있는가?
11. 파티원이 사망해 소유 카드가 제거되어도 남은 캐릭터의 핵심 플레이가 붕괴하지 않는가?
12. 조작 카드가 실행선·대형·대상·비용·수치·텍스트·상태 중 컨셉에 맞는 항목을 바꾸는가?
13. 지속 카드와 전투 한정 소멸 카드의 유지·교체·복구 시점이 명확한가?
14. 조작 대상 수와 비용이 실제 UI에서 이해 가능한가?
15. 무작위 대상 카드가 실패 대상 없이 `CombatState`의 시드 RNG로 결정론적으로 작동하는가?
16. 반복 가능한 상태와 지속 규칙이 장기전에서 무한 성장하거나 무한 순환하지 않는가?
17. 키워드가 절이나 대화에서 처음 등장할 때 작동 방식부터 설명됐는가?

## 8. 범위 밖

- 최종 수치 밸런스와 희귀도
- 카드 강화판·업그레이드 경로
- 카드 아트·캐릭터 외형·서사
- 적 카드풀과 캐릭터별 전용 적
- 신규 효과·상태·조작의 실제 구현 계획
- 카드 보상 가중치와 런 중 등장 확률
