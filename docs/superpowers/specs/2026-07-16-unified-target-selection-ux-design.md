# 명시적 대상 선택 UX 통합 설계

## 1. 목적

플레이어가 직접 대상을 클릭하는 모든 카드에 같은 선택 표현과 조작 규칙을 적용한다.
현재 실행 순서 카드 대상에는 화살표가 표시되지만 아군 대상에는 표시되지 않는 불일치를 제거하고,
향후 적 대상 카드가 추가되어도 같은 흐름을 재사용할 수 있게 한다.

대상을 직접 고르지 않는 카드는 기존 조작을 유지한다. 손패 카드를 선택하면 카드가 마우스를 따라가고,
실행 순서 영역을 클릭하면 배치한다.

## 2. 범위

### 포함

- 아군, 적, 실행 순서 카드 등 플레이어가 직접 클릭하는 모든 명시적 대상
- 단일 대상 및 둘 이상의 다중 대상
- 선택 카드 고정, 타겟팅 화살표, 대상 후보 강조, 비대상 영역 딤 처리
- 다중 대상의 선택 표시와 확인 버튼
- 취소 및 선택 도중 대상이 무효화되는 경우의 복구
- 순수 C# 선택 상태의 헤드리스 테스트와 Unity 표현 테스트

### 제외

- 대상 선택이 필요 없는 카드의 기존 마우스 추적 배치 방식 변경
- 카드 효과 및 밸런스 변경
- 적 AI가 실행 시점에 자동으로 대상을 결정하는 규칙 변경
- 카드 저작 데이터 전체를 새로운 대상 메타데이터 체계로 이전하는 작업

## 3. 공통 상호작용 규칙

### 3.1 대상이 없는 카드

기존 흐름을 유지한다.

1. 손패 카드를 클릭한다.
2. 선택한 카드가 커서를 따라간다.
3. 실행 순서 영역을 클릭하면 카드가 배치된다.

### 3.2 명시적 대상이 있는 카드

1. 손패 카드를 클릭하면 해당 카드를 선택 상태로 고정한다.
2. 선택한 손패 카드의 화면상 중심점에서 현재 커서까지 타겟팅 화살표를 표시한다.
3. 현재 유효한 대상은 공통 강조색의 테두리로 표시한다.
4. 대상이 아닌 영역은 어둡게 처리하되, 선택 가능한 대상과 안내 문구는 가리지 않는다.
5. 유효한 대상을 클릭하면 선택 상태에 기록한다.

화살표 시작점은 대상 종류나 선택 단계와 관계없이 항상 처음 선택한 손패 카드에 둔다.
다중 대상 카드도 첫 번째 대상에서 두 번째 대상으로 화살표를 연결하지 않는다. 여러 대상 사이에
상호작용이 있다는 잘못된 의미를 피하고, 선택한 카드가 모든 대상에 작용한다는 의미를 유지하기 위함이다.

### 3.3 단일 대상

- 확인 버튼을 표시하지 않는다.
- 유효한 대상을 클릭하면 즉시 선택을 확정하고 카드 플레이를 요청한다.
- 요청이 거부되면 카드와 자원을 소비하지 않고 방금 고른 대상을 선택 해제한다. 선택 모드는 유지하고
  현재 유효한 후보를 다시 표시해 플레이어가 대상을 다시 클릭하게 한다.

### 3.4 다중 대상

- 이미 선택한 대상에는 선택 순서를 나타내는 번호 배지를 표시한다.
- 같은 대상을 중복 선택할 수 없다.
- 필요한 대상을 모두 선택하기 전에는 확인 버튼을 표시하지 않는다.
- 카드가 요구하는 대상 수가 2개 이상이고 필요한 대상을 모두 선택한 뒤에만 확인 버튼을 표시한다.
- 확인 버튼을 누르기 전에는 카드와 자원을 소비하지 않는다.
- 확인 시점에 모든 대상을 다시 검증하고, 하나라도 무효라면 플레이하지 않고 유효한 선택만 남겨
  선택을 계속할 수 있게 한다.

### 3.5 취소

빈 영역 클릭 또는 기존 전투 화면의 취소 입력으로 선택을 취소한다. 취소 시 다음 상태를 한 번에 초기화한다.

- 선택한 손패 카드의 고정 및 선택 테두리
- 타겟팅 화살표
- 대상 후보 및 선택 완료 강조
- 비대상 영역 딤
- 확인 버튼
- 선택 상태가 보관한 대상 목록

취소는 카드, 운명력, 실행 순서에 변화를 주지 않는다.

## 4. 구조

### 4.1 순수 선택 상태

UnityEngine을 참조하지 않는 순수 C# 선택 상태가 다음 정보와 전이를 관리한다.

- 선택한 손패 인덱스
- 요구 대상 수
- 대상 영역을 구분하는 타입 안전 식별자
- 선택한 대상 식별자 목록
- 유휴, 대상 선택 중, 확인 가능 상태
- 대상 선택, 중복 거부, 확인, 취소 전이

단일 대상은 첫 유효 선택에서 완료 명령을 만든다. 다중 대상은 요구 개수를 채운 뒤 확인 가능 상태가 되고,
명시적인 확인 입력에서만 완료 명령을 만든다. 이 상태는 대상의 Unity 뷰나 좌표를 알지 않는다.

### 4.2 Unity 선택 컨트롤러

`CardSelectionController`가 모든 카드 선택 표현을 소유한다.

- 대상이 없는 카드의 마우스 추적 배치
- 명시적 대상 카드의 손패 고정과 화살표 추적
- 대상 후보, 선택 순서, 딤, 확인 버튼 표시
- 선택 완료 및 취소 시 표현 초기화

아군 대상 흐름을 `BattleScreenController`에 별도로 유지하지 않고 공통 선택 컨트롤러를 통과시킨다.
대상 뷰는 클릭 시 자신의 타입 안전 식별자를 전달하고, 선택 컨트롤러는 순수 선택 상태의 결과만 반영한다.

### 4.3 전투 화면 컨트롤러

`BattleScreenController`는 다음 조정 책임만 가진다.

1. 카드 규칙에서 대상 종류와 요구 개수를 얻는다.
2. 현재 유효한 대상 식별자 집합과 함께 선택을 시작한다.
3. 선택 완료 결과를 `DeckCombatSession`의 실행 카드 또는 개입 카드 API 호출로 변환한다.
4. 세션이 플레이를 거부하면 메시지와 대상 후보를 갱신한다.

타겟팅 화살표, 딤, 확인 버튼 같은 표현 분기는 전투 화면 컨트롤러에 두지 않는다.

## 5. 데이터 흐름

```text
손패 카드 클릭
  -> 카드 대상 요구사항 계산
  -> 공통 선택 상태 시작
  -> 선택 컨트롤러가 화살표·후보·딤 표시
  -> 대상 뷰 클릭
  -> 순수 선택 상태가 대상 기록 또는 완료 명령 생성
  -> 단일 대상은 즉시, 다중 대상은 확인 후 전투 화면에 결과 전달
  -> 세션이 대상을 재검증하고 카드 플레이
  -> 성공 시 전체 화면 갱신, 실패 시 선택 후보와 메시지 갱신
```

## 6. 유효성 및 오류 처리

- 선택 시작 전에 대상 수가 부족하면 선택 모드에 진입하지 않고 안내 메시지를 표시한다.
- 선택 도중 대상이 사망하거나 제거되면 해당 대상을 후보와 선택 목록에서 제거한다.
- 중복 대상 클릭은 상태를 변경하지 않는다.
- 세션 검증 실패는 카드나 자원을 소비하지 않는다.
- 필수 Unity 참조가 누락된 경우 조용히 다른 UX로 대체하지 않고 초기화 단계에서 명확한 오류로 드러낸다.
- 단일 대상 검증 실패 후 유효한 후보가 남아 있으면 선택한 대상을 지우고 선택 모드를 유지한다.
- 다중 대상 검증 실패 후 유효한 후보가 남아 있으면 무효 대상만 지우고 유효한 선택을 유지한다.
- 검증 실패 후 유효한 후보가 하나도 없으면 안내 메시지를 표시하고 선택을 취소한다.
- 성공, 사용자 취소, 유효 후보 소진에 따른 강제 종료는 같은 정리 메서드를 사용한다.

## 7. 검증

### 7.1 헤드리스 테스트

- 단일 대상 선택은 확인 없이 즉시 완료된다.
- 대상 수가 2개 이상이면 모든 대상을 선택해도 확인 전에는 완료되지 않는다.
- 다중 대상의 필요한 선택이 끝난 뒤 확인하면 완료된다.
- 중복 대상은 선택 개수를 늘리지 않는다.
- 취소하면 선택 목록과 단계가 유휴 상태로 돌아간다.
- 단일 대상 완료가 거부되면 선택한 대상을 지우고 단일 대상 선택 단계로 돌아간다.
- 무효화된 대상을 제거하면 필요한 선택 수를 다시 채워야 한다.
- 같은 입력 시퀀스는 같은 선택 결과를 만든다.

### 7.2 Unity EditMode 테스트

- 아군과 실행 순서 카드 대상 모두 같은 화살표 표시 경로를 사용한다.
- 대상이 없는 카드에는 화살표가 나타나지 않고 기존 마우스 추적 카드가 나타난다.
- 단일 대상 선택에는 확인 버튼이 나타나지 않는다.
- 다중 대상은 필요한 선택이 끝난 뒤에만 확인 버튼이 나타난다.
- 취소와 완료 시 화살표, 강조, 딤, 확인 버튼이 모두 초기화된다.

### 7.3 수동 플레이 검증

- 아군 단일 대상 카드에서 손패 카드부터 아군까지 화살표가 표시되고 클릭 즉시 카드가 배치된다.
- 실행 순서 단일 대상 카드도 같은 방식으로 동작한다.
- 실행 순서 다중 대상 카드에서 화살표 시작점이 선택한 손패 카드에 계속 고정된다.
- 다중 대상의 선택 순서가 보이고, 필요한 대상을 모두 고른 뒤에만 확인 버튼이 나타난다.
- 대상이 없는 실행 카드는 기존 마우스 추적 및 실행 순서 영역 클릭 방식으로 배치된다.

## 8. 완료 기준

- 플레이어가 직접 대상을 클릭하는 현재의 모든 카드가 동일한 화살표 기반 선택 흐름을 사용한다.
- 대상 종류에 따라 전투 화면 컨트롤러가 서로 다른 선택 표현을 직접 관리하지 않는다.
- 단일 대상에서는 확인 버튼이 전혀 나타나지 않는다.
- 다중 대상에서는 필요한 대상을 모두 선택한 뒤에만 확인 버튼이 나타난다.
- 대상 없는 카드의 기존 배치 UX와 게임 규칙, 결정론이 유지된다.
- 관련 헤드리스 테스트와 Unity 컴파일 검증이 통과한다.
