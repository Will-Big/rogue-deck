HandFan 시각 테스트 씬

구현 완료 · Play 검수 대기 · 2026-09-22 · 구현 상세

무엇을 만드나

빈 핸드에 카드를 한 장씩 추가하고, 맨 뒤 카드를 한 장 제거하거나 전체를 비우는 독립 씬이다. 기존 HandFan과 카드 프리팹으로 간격·각도·축소·호버를 눈으로 확인한다. 실제 드로우·덱 이동 규칙과 새 연출은 포함하지 않는다.

화면 상단에는 추가 / 1장 제거 / 전체 비우기 버튼과 장수, 하단에는 기존 전투 씬 구성을 기준으로 한 HandFan을 둔다. 레이아웃과 Play의 최종 판단은 사용자가 한다.

구조

객체책임모르는 것
CardSourceJSON 카드를 표시 데이터로 변환현재 핸드·버튼
SandboxState테스트 목록·선택 상태 관리전투 규칙·Unity 객체
Panel조작 입력·상태 표시카드 정의·변경 정책
Controller호출 순서와 연결규칙 판단·표시 변환
최신 HandFan + HandFanLayoutView카드의 핸드 표현과 인스펙터 배치 설정테스트 버튼·전투 진행

연결은 전용 Controller에 모인다. 목록 정책·표시 변환을 별도 객체에 두어 Controller는 배선만 맡긴다. 기존 전투 관리자를 확장하지 않는다.

의존 방향

저장된 테스트 프리팹이 모든 참조를 보유한다. 런타임 이름 검색이나 즉석 UI 생성은 추가하지 않는다.

교체 가능한 것과 고정하는 것

인스펙터에서 테스트 카드 ID 순서와 기존 아트·카드 프리팹 참조를 교체한다. 실행 중에는 목록·선택만 바뀐다. 이번 구성은 기존 HandFan을 쓰는 수동 조작으로 고정하며, 미래 기능용 추상화는 두지 않는다.

대안과 선택

별도의 가짜 HandFan은 실제 화면과 달라질 수 있어 만들지 않는다.

이 선택으로 나중에 어려워지는 것

여기서 카드가 줄어드는 모습이 맞아도 실제 덱 이동이나 드로우 규칙이 맞다는 보장은 없다. 실제 게임 규칙을 검증할 때는 별도의 연결이 필요하다. 목록 변경은 기존 SetCards의 전체 뷰 재생성을 그대로 따르므로, 연속 이동 연출이나 대량 카드 성능 평가용으로는 제약이 있다.

현행 근거: Assets/Unity/Scripts/Cards/HandFanView.cs의 SetCards, HandFanLayoutView.cs, CardPresentation.cs의 FromDefinition.

실행 예시

인스펙터 ID 목록을 [brace, quick_cover]로 지정한다. CardSource가 기존 JSON과 설명 카탈로그로 표시 데이터를 준비한다. 빈 상태에서 추가를 세 번 누르면 State는 [brace, quick_cover, brace]가 되고 Controller가 SetCards로 전달해 Panel에 3장을 표시한다.

1장 제거를 누르면 선택 여부와 무관하게 마지막 brace가 빠지고 [brace, quick_cover]가 표시된다. 전체 비우기는 0장으로 돌아가며 다음 추가는 다시 brace다. 미1장 제거는 비활성화한다.

구현 순서와 확인

  1. 전용 워크트리에서 테스트 상태·콘텐츠 변환·패널·조정자를 구현한다. 선택 여부와 무관한 마지막 카드 제거와 초기화, 잘못된 콘텐츠를 검사한다.
  2. 독립 씬과 재사용 프리팹을 저장하고 실제 씬의 참조·입력 배선을 EditMode로 검증한다. 전체 Tools/verify.sh도 통과시킨다.
  3. 사용자가 Play에서 0 → 1 → 5 → 12장, 맨 뒤 제거, 전체 비우기, 화면 폭 변경, 호버를 확인한다.

기존 HandFan에서 발견한 문제는 기록하고 별도 범위로 다룬다. master 머지는 별도 승인 후 진행한다. 구현과 자동 검증을 마쳤다. 사용자 Play 검수와 master 머지는 대기 중이다. 참조 누락으로 표시가 실패하면 오류를 표시하고 조작을 중단한다. 참조를 수정한 뒤 씬을 다시 시작하면 된다.
