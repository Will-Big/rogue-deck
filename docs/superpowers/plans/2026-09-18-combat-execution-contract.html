합의한 전투 규칙을
일곱 작업으로 전환한다

이 세션에서는 계획만 작성한다. 소스·카드 JSON·편집 도구 변경은 별도 구현 요청 이후 전용 워크트리에서 수행한다. 다중 적 정책은 별도 작업 범위다.

상세 작업·인터페이스·실패 테스트 · 승인된 구조 설계

무엇을 만드나

효과마다 위치를 다시 선택하고 직접 반응을 해결하며, 카드 종료에 승패를 판정하는 구조로 전환한다. 카드 시작 조건과 소비 결과 의존을 분리하고, 상태 만료는 공통 턴 시점으로 표현한다.

기존 효과 처리기·등록 구조를 유지한다. 코드에 여러 계약을 오래 공존시키기보다, 데이터 변경과 도구 왕복을 같은 작업에서 전환한다.

작업별 책임과 완료 결과

작업단일 책임이 작업이 다루지 않는 것
T1 실행선자리와 실행 이력의 일관성피해·반응 계산
T2 데이터 계약시작 조건과 수행 결과의 구분반응 시점 변경
T3 대상 해석효과 단위 위치 선택카드 종료 승패
T4 반응사건의 직접 반응 해결턴 진행·게임 카드 추가
T5 종료 경계카드 단위 완료개별 효과 공식
T6 상태 수명공통 시점 만료런 지속값 구조
T7 회귀전체 계약의 통합 검증새 게임 기능·표현 연출

각 작업은 실패 테스트, 구현, 검증, 커밋 순서로 수행한다. T2의 범위가 넓은 이유는 게임과 편집 도구가 서로 다른 데이터 규격을 쓰는 중간 상태를 피하기 위해서다.

의존 방향

새 중앙 관리자로 모든 규칙을 모으지 않는다. 카드 실행기는 효과 진행을, 효과 실행기는 대상·사망·직접 반응의 경계를 연결한다. 계산은 등록된 개별 처리기에 남긴다.

확장 축

효과·조건·사건·반응 능력·위치 선택은 키와 처리기 등록으로 확장한다. 피해 보정과 방어 흡수는 반응 연쇄가 아니므로 그대로 적용한다. 반응 기원 표시가 추가 능력 발동만 차단한다.

고정 계약은 효과 순차 처리, 반응 연쇄 금지, 카드 종료 승패, 패배 우선이다. 수명 정책은 공통 단계 방문으로 만료하며 방어 이름을 검사하지 않는다. 전역 관찰자 순서와 다중 대상 정량 지불은 이번 수용 범위 밖이다.

대안과 기각 이유

채택: 계약별 검증 후 전환

회귀 원인을 작업 단위로 좁히고 변경 책임을 검토할 수 있다.

기각: 한 번에 전체 교체

데이터·순서·반응·표시의 실패가 겹쳐 규칙 변경과 구현 오류를 구분하기 어렵다.

이 선택으로 어려워지는 것

  • T2는 정의·JSON·설명·편집 도구를 같이 변경해야 한다. 의미가 불명확한 기존 조건은 자동 변환할 수 없다.
  • 순서 의미가 바뀌므로 기존 테스트 기대값 중 일부를 교체해야 한다. 단순 기대값 변경이 아니라 승인된 사례로 변경 이유를 연결한다.
  • 별도 다중 적 작업과 세션 파일이 겹칠 수 있다. 최신 정책 호출부는 보존하고 본 계획의 턴 경계만 연결한다.
  • 스키마 테스트가 파일을 갱신할 수 있어 생성물도 검토하고 재검증해야 한다.

실행 예시

가상 카드: 피해 3 → 자신 방어 3 → 피해 3. 아군 HP 10, 적 HP 8, 적의 반격은 피해 2.

순서 / 담당확인할 결과
T3 효과 대상 선택, T4 첫 피해·반격적 HP 5, 아군 HP 8
T3 자신에게 방어아군 방어 3
T4 두 번째 피해·반격적 HP 2, 아군 HP 8·방어 1
T5 카드 완료전투 계속. 반응이 추가 반응을 만들지 않음
T7 로그·왕복 검증카드 효과 순서와 실제 상태 변경이 동일하게 관측됨

설계의 검증 사례 V01~V22를 각 작업에 대응시켰다. 직접 반응의 사망 능력, 방어 획득 반응, 사망 후 현재 카드의 계속 수행도 별도 테스트로 포함한다.

인계 기준

구현 담당자는 별도 요청 후 워크트리를 만들고 현재 코드를 다시 확인한다. 단계별 헤드리스 테스트, 데이터 전환 시 도구 왕복, 최종 전체 검증을 수행한다. 의미가 모호한 데이터나 승인 설계와 충돌하는 규칙은 임의로 고치지 않는다.

이 계획에는 향후 추가할 API와 테스트 코드가 포함되어 있지만 아직 실행하거나 소스 파일로 작성하지 않았다. 구현 시작은 별도 사용자 요청으로 결정한다.
